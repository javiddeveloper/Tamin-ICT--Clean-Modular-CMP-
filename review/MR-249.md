## خلاصه‌ی تغییر

This MR adds a new employer-facing "Workshop Inspections" list screen (بازرسی‌های کارگاه) plus an objection-submission wizard, mirroring the existing insured-side inspection flow end-to-end: a new getAllManager API/data-source/repository/use-case chain, a new WorkshopInspectionViewModel/Contract/Screen built by reusing the insured-side wizard steps and shared components, and an unrelated refactor of TaminStyledTextField's click-overlay layout. Test coverage for the new network/data/domain layers is solid and mirrors existing patterns. The main functional risk is that the in-app search only filters already-loaded pages (pagination is paused while a filter is active), so a user searching for an inspection that hasn't been paged in yet will see a false 'not found' — this is disclosed in a code comment as an accepted limitation pending backend filter support, but it is still a real gap worth confirming with product/design. Business-flow parity with old_android (e.g., whether mobile was optional or required in the legacy employer objection flow) could not be checked because old_android/ is not present in this worktree.

## یافته‌های ریویو (قضاوت مدل)

### 1. Search only covers already-loaded pages

🟠 **Medium** · منطق · `feature/taminServices/src/commonMain/kotlin/com/tamin/taminhamrah/feature/taminServices/workshopInspection/contract/WorkshopInspectionContract.kt:60`

`filteredInspections` filters the in-memory `inspections` list. `WorkshopInspectionScreen.kt:206` disables `OnLoadMore` whenever `appliedFilter != null`, so applying a search never triggers loading further pages. A workshop with more inspections than fit on the first page (offset-paginated via `Paginator`) will show 'موردی یافت نشد' for an inspection or workshop code that genuinely exists on the server but simply hasn't been paged in yet. The doc comment above `WorkshopInspectionFilter` acknowledges this is intentional pending a confirmed backend filter contract on `inspection-header/get-all-manager`, so this is a known trade-off rather than an oversight, but it will read as a bug to end users and should be confirmed with product/design before merge.

**پیشنهاد:**
```
Either wire the applied filter into the query sent to getAllManager (if the backend can support it) or, short of that, keep paginating while a filter is active and only stop once inspectionsEndReached, so a match anywhere in the full result set is found.
```


### 3. Unrelated shared-component refactor bundled into a feature MR

🔵 **Low** · خوانایی/سبک · `core/core-ui/src/commonMain/kotlin/com/tamin/taminhamrah/ui/components/TaminStyledTextField.kt:124`

This MR is scoped to EM-2663 (workshop inspections), but it also restructures `TaminStyledTextField` — a component used across ~59+ call sites app-wide — moving the click-overlay Box to wrap only the input Row instead of the whole Column. The new layout is more correct (label/error text is no longer swallowed by the click target), but bundling a shared-component change with unrelated feature work makes this MR's blast radius harder to review and to bisect if something regresses elsewhere.

**پیشنهاد:**
```
Split this into its own small MR/commit with its own rationale, independent of the workshop-inspection feature.
```
