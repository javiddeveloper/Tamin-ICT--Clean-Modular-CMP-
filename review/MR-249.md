## یافته‌های ریویو (قضاوت مدل)

### 1. Search filter only covers pages already fetched, silently

🟠 **Medium** · منطق · `feature/taminServices/src/commonMain/kotlin/com/tamin/taminhamrah/feature/taminServices/workshopInspection/contract/WorkshopInspectionContract.kt:60`

filteredInspections filters the in-memory `inspections` list with String.contains — items on a page the paginator hasn't loaded yet (10/page, per InspectionRepositoryImplTest) are simply absent from the result. WorkshopInspectionScreen shows the generic 'no result' empty state in that case (workshop_inspection_search_empty_subtitle: 'حذف فیلتر را امتحان کنید'), which reads as 'this inspection doesn't exist' rather than 'not loaded yet'. The code comment at the top of the file acknowledges the endpoint has no confirmed server-side filter and calls this the 'honest' behavior, but the UI gives no indication the search is partial.

**پیشنهاد:**
```
Either page through the rest of the list when a filter is applied before showing the empty state, or change the empty-state copy to make clear the search only covers what has loaded so far.
```


### 2. CancellationException swallowed in submit and PDF download

🟠 **Medium** · مدیریت خطا · `feature/taminServices/src/commonMain/kotlin/com/tamin/taminhamrah/feature/taminServices/workshopInspection/ui/WorkshopInspectionViewModel.kt:189`

handleSubmitRequest (line ~189-198) and handleDownloadReportPdf (line ~200-211) both catch (e: Exception) with no CancellationException re-throw. If the user leaves the objection wizard or closes the PDF viewer while the coroutine is still in flight, the resulting cancellation is caught as a generic failure: isLoading is reset to false and, in the submit case, a 'no connection'-style toast is shown for a request that may already have reached the server. The same shape was copied into InspectionRemoteDataSourceImpl.getAllManager (core/core-network/.../InspectionRemoteDataSourceImpl.kt, new method) which also has no CancellationException rethrow. This repeats the project's Kotlin/KMP rule that CancellationException must propagate.

**پیشنهاد:**
```
Add `catch (e: CancellationException) { throw e }` before the generic `catch (e: Exception)` in both handlers, and in getAllManager's try/catch.
```


### 4. Submit and PDF-download failure paths are untested

🔵 **Low** · تست · `feature/taminServices/src/commonTest/kotlin/com/tamin/taminhamrah/feature/taminServices/workshopInspection/WorkshopInspectionViewModelTest.kt:166`

submitRequest_success_updatesUiStateIsSubmitted (line 166) and downloadReportPdf_success_updatesUiStateWithViewerPdf (line 194) are the only tests exercising SubmitRequest/DownloadReportPdf, and both only set up the success case (repository.shouldThrowError is used elsewhere for the initial list load and job fetch, never for submit or PDF download). The failure branches in handleSubmitRequest/handleDownloadReportPdf (the ShowToast + Loading(false)/ViewerDownloadFailed paths) have no test asserting the toast fires and isLoading resets.

**پیشنهاد:**
```
Add a test that sets repository.shouldThrowError before SubmitRequest/DownloadReportPdf and asserts the ShowToast event and the reset loading/viewerDownloadFailed state.
```


### 5. Duplicate imports added by this MR

🔵 **Low** · خوانایی/سبک · `shared/src/commonMain/kotlin/com/tamin/taminhamrah/ui/navigation/FeatureNavigation.kt:29`

This MR's own diff (against merge-base dc572ccf3) adds `import ...navigateToInspection` and `import ...navigateToEmployerOnlineServices` a second time (lines 29/31 and 28/33) alongside the new `navigateToWorkshopInspection` import. Kotlin accepts the duplicates so it still compiles, but it's leftover noise from how the import block was edited.

**پیشنهاد:**
```
Remove the two repeated import lines, keeping only the new `navigateToWorkshopInspection` import.
```
