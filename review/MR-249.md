## Round 1 items

### 1. ✅ Fixed

`handleSubmitRequest`, `handleDownloadReportPdf` and `getAllManager` now rethrow `CancellationException`
before the general catch. `getAllManager` does it with an explicit catch rather than `errorParser.safeCall`,
which is fine and consistent with the five older functions in the same file.

### 2. ✅ Fixed

The screen no longer switches paging off while a filter is applied, and a `LaunchedEffect` keeps
loading the next page whenever the filter matches nothing and pages remain; while it does, a skeleton is
shown, and «موردی یافت نشد» appears only once `inspectionsEndReached`. I read the loop for runaway
requests: it re-fires only when the loading flag drops, stops on a paging error and at the last page.

Remaining note, not blocking: a filter that matches *some* loaded rows does not keep paging on its own —
`OnLoadMore` fires only when the end of the list first comes into view — so a second match on a later
page appears only after further scrolling. For a search by inspection or workshop number that is
acceptable. The paging rule lives in the composable, so it has no unit test.

### 3. ⬜ Needs confirmation — mobile and banner fixed, three points remain

Fixed: mobile is optional again and validated with the legacy `^09\d{9}$` pattern (contract tests added
for a blank mobile and for an 11-digit non-mobile), and the banner now says to correct «the editable
fields». Still open, none of them changed in this round:

- **Email and mobile are not pre-filled and locked from the profile.** Legacy filled both from the
  profile and locked whichever it filled (`SubmitInspectionRequestFragment`, `enableView(false)`); the new
  form fills only name, national code and mobile, and leaves them editable.
- **Read-only workshop name and branch.** Legacy let the user edit the name and choose the branch from a
  list; here they are locked to the tapped row, and step 2 needs both to be non-blank. The new comment
  explains that the insured-side step does the same for objections, which is a reason for consistency, but
  legacy is the reference. A row the server returns with either blank leaves the user stuck at step 2.
- **Payload.** The request now carries the real inspection and insurance numbers where legacy sent empty
  strings; still to be confirmed with the backend team.

## 7. The double-submit guard — ✅ fixed

The guard is now `private var isSubmitting`, checked and set at the top of `handleSubmitRequest` before
anything suspends, and cleared in a `finally` — so it also resets when the call is cancelled, fails, or
succeeds. The test now runs on a `StandardTestDispatcher` and holds the first submit in flight before the
second arrives. I checked it both ways: it passes on this commit, and with the old `uiState.value.isLoading`
guard put back it fails (2 submit calls), so it is a real regression test and not a pass-through.

## 8. Comments that pointed at this review — ✅ fixed

The «MR !249» references in `InspectionRequestSharedFields.kt` and `WorkshopInspectionContractTest.kt` and
the `.claude/rules/state-management.md` pointer are gone; the comments now state the rule itself.

## What was done well

- **Every round-1 point that could be settled in code was**, including the mobile rule, which now
  matches legacy exactly and has contract tests on both sides of it.
- **The auto-paging loop is careful**: it keys on the loading flag, stops on error and at the end, and
  shows a skeleton instead of a premature «not found».
- **The shared fields kept the layout intact** (mobile on its own line, landline and email side by
  side) and left the intentional differences — mobile validity, label, required marker — as parameters,
  so the insured flow's behaviour did not change.
- **The cancellation fix reached the data source too**, not just the two ViewModel sites.
- **The regression test was written to fail for the right reason**: its comment says why it needs a
  non-eager dispatcher, and it fails when the old guard is restored.
- **Failure-path tests assert the state, not just the toast**: loading reset, `isSubmitted` false,
  `viewerDownloadFailed` true, no PDF left over.
