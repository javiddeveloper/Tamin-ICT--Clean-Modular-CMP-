## 1. `CancellationException` swallowed by raw `try/catch(e: Exception)` — Fixed

**File:** `CompleteEmployerInfoViewModel.kt:140-190`

All three occurrences are fixed. `loadUserAndWorkshops()`'s profile load now uses `.catch { }` on
the use-case `Flow` (auto-rethrows cancellation), and its agreements load — a plain suspend call,
not a `Flow` — now does:

```kotlin
try {
    val agreements = getEmployerAgreements(WorkshopListQuery())
    ...
} catch (e: CancellationException) {
    // A suspend call, so there is no `catch` operator to lean on: cancellation has to be
    // let through by hand or leaving the screen mid-load reports itself as an error.
    throw e
} catch (e: Exception) {
    emit(CompleteEmployerInfoPartialState.Error(e.toSingleLineMessage()))
}
```

`loadProvinces()` is likewise switched to `Flow.catch { }`. Correct fix, and the comment explains
*why* the suspend-call site needs the explicit `CancellationException` re-throw that the `Flow`
sites get for free — worth keeping as a reference for the next place in this codebase that mixes
a raw suspend call with `Flow`-based sibling calls in the same loader.
