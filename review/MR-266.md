## 1. Empty `dismissButton` leaves a stray gap — Low

**File:** `feature/taminServices/src/commonMain/kotlin/com/tamin/taminhamrah/feature/taminServices/constructionInsurance/paymentSheet/ui/PaymentSheetScreen.kt:236-280`

The issue-confirmation dialog now puts both cancel and confirm inside a single `Row` passed as
`confirmButton`, and passes `dismissButton = {}` since the second slot is no longer needed:

```kotlin
confirmButton = {
    Row(...) {
        TaminOutlinedButton(...)  // انصراف
        Box(...) { TaminFilledButton(...) }  // تایید و صدور
    }
},
dismissButton = {},
```

`TaminConfirmationDialog`'s own layout (`TaminConfirmationDialog.kt:125-130`) always renders both
slots inside a `Column(verticalArrangement = Arrangement.spacedBy(10.dp)) { confirmButton(); dismissButton() }`.
`spacedBy` inserts spacing for every child regardless of its measured size, so the empty
`dismissButton()` composable still adds a 10dp gap below the button row — a minor but visible
extra space at the bottom of this one dialog compared to every other caller of this component.

**Suggested change:** give `TaminConfirmationDialog` a `dismissButton: (@Composable () -> Unit)? = null`
overload (skip the second `Column` child, and its spacing, when null) rather than asking callers to
pass an empty lambda; or, short of touching the shared component, wrap the whole button block in
`confirmButton` and pass nothing else, if the API allows it.

**Author response (h_arabameri) — disagree, no code change:** an empty `dismissButton = {}` emits no
layout node, so the button `Column` has exactly one measurable child. `Arrangement.spacedBy` only
inserts spacing *between* placed children (n − 1 gaps), so with one child there is no 10dp gap — it
would only appear if the slot emitted a zero-size node (e.g. a `Box` or `Spacer`), which it doesn't.
This is also already the established usage: ~50 other `TaminConfirmationDialog` callers pass
`dismissButton = {}` (including the processing-notice dialog directly above, `PaymentSheetScreen.kt:251`),
so this dialog renders its bottom spacing the same as they do. Making the slot nullable would be a
harmless API nicety, but it's a shared core-ui change with no visual effect and belongs outside this MR.
