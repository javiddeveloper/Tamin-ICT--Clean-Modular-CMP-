## 1. New status-check paths are untested — Medium

**File:** `core/core-network/src/commonMain/kotlin/com/tamin/taminhamrah/tools/BaseDTO.kt` (`requireSuccessStatus`, `extractTypedData`)

`requireSuccessStatus()` now replaces several hand-written `if (response.status !in 200..299)`
blocks (save-contact and other calls whose reply carries nothing to read), and `extractTypedData`
now maps 4xx/5xx through `HttpStatusErrorMapper` instead of the old `"CLIENT_ERROR: …"` string.
The tests added in this MR cover the converter, `toErrorUri()`, `safeCall` and plain-text errors,
but neither of these two paths.

> **سناریوی بیزینسی که تست ندارد:** کاربر عملیاتی را ثبت می‌کند که پاسخ سرور محتوایی ندارد (مثل
> ذخیره‌ی اطلاعات تماس) و سرور با یک خطای معمولی (مثلاً ۴۰۰ یا ۵۰۰) جواب می‌دهد. انتظار این است که
> کاربر همان پیام خطای مربوط به آن وضعیت را ببیند و عملیات موفق تلقی نشود؛ و همین‌طور برای
> عملیاتی که پاسخ دارد ولی سرور خطای ۴xx/۵xx برمی‌گرداند، پیام درست و متناسب با نوع خطا نشان داده
> شود. هیچ تستی این دو مسیر را پوشش نمی‌دهد.

**Suggested change:** add tests for a 2xx (no error), a 4xx and a 5xx reply through
`requireSuccessStatus()`, and for `extractTypedData` with a 4xx/5xx status asserting the mapped
error and that the server's own message is preferred when present.

## 3. Retirement intro reports an error when nothing is wrong; module tests are red — Medium

**File:** `feature/retirementPension/src/commonMain/kotlin/com/tamin/taminhamrah/feature/retirementPension/ui/RetirementPensionViewModel.kt` (intro load, ~line 285–316)

Commit `0cb0e77fe` collects every failed intro call in `failures` and shows the first one as an error
toast. `checkRetirementStatusUseCase().first()` throws `NoSuchElementException` when the call
completes without a value, so an account with no retirement request on file (or a `null` body)
now gets an error toast on every open of the screen, where before it was silently "no request".
The unit tests confirm it: `rulesStep_viewRules_emitsOpenRulesDocumentEvent`,
`authenticationStep_verifyOtp_success_prefillsIdentityAndAdvances` and
`init_whenTheAgeCallFails_reportsItAndClaimsNoAgePass` fail on this commit (the first two receive a
`ShowError` on the happy path; the third expects the raw exception text but gets the generic
message). The MR was pushed with a red module.

> **مغایرت بیزینسی:** در نسخه‌ی قدیمی، نبودن «درخواست بازنشستگی قبلی» حالت عادی بود و کاربر هیچ
> خطایی نمی‌دید. الان کاربری که هنوز درخواستی ثبت نکرده، با هر بار ورود به صفحه‌ی مقدماتی یک پیام
> خطا می‌بیند، چون «پاسخ خالی» با «شکست تماس» یکی گرفته شده است. باید فقط شکست واقعی تماس (قطع
> اینترنت، خطای سرور) گزارش شود، نه پاسخ بدون محتوا.

**Suggested change:** treat an empty status reply as "no request" (`firstOrNull()`) and report
only real exceptions; fix the three tests (give the fake a status result, and assert the mapped
message rather than the raw one).

**Round 3:** `6cc6b8121` fixes this from the other end — `checkRetirementStatus()` now always
emits a `RetirementStatusDN` (with null fields for "no request on file") instead of completing
empty, per the comment: *"the live `checkRequests` reply is an object of nulls, never an empty
body."* If that description of the real endpoint is accurate this is a correct, arguably better
fix than the suggested `firstOrNull()` (the VM's `failures`-toast logic is untouched and still
correct for a real failure). All three tests pass now, confirmed by running
`:feature:retirementPension:testDebugUnitTest`.

## 4. Copy-pasted `catch` chains instead of one shared error path — Medium

**File:** `core/core-network/src/commonMain/kotlin/com/tamin/taminhamrah/dataSource/**` (e.g. `WorkersPaymentRemoteDataSourceImpl`)

Round 1 praised `safeCall` as the single place errors are mapped. Since then the MR replaced it
in most data sources with the same block written out by hand — roughly 130 identical
`SocketTimeoutException` catches and 127 `NO_CONNECTION_ERROR` fallbacks — while about ten data
sources and `HomeRepositoryImpl` still use `safeCall`. So there are now two error paths that can
drift apart (the timeout → `SERVICE_TIMEOUT` rule already exists in only one of them), and every
new data source has to remember to paste the chain. The last branch of each chain still turns any
unrecognized exception into "no connection", which is the behaviour round 1 said the MR fixed.

**Suggested change:** put the chain back into one helper (`safeCall`, with the new timeout and
`INTERNAL_ERROR` rules added to it) and have every data source use it; keep an unrecognized
exception as an unknown error, not a connection error.

**Round 3:** accepted as-is — the reviewer will address this app-wide, across every data source in
one pass, rather than as a fix scoped to this MR.

## What was done well

- **`safeCall` keeps `CancellationException` out of the error mapping**, and the ~20 data sources
  now share one path instead of 20 copies of the same try/catch — the old blocks reported every
  unrecognized failure (including a screen the user had left) as "no connection".
- **Only reading is relaxed** in `LenientReplyConverter` (`explicitNulls = false` on the decode
  side only), so request bodies stay byte-for-byte unchanged; the API tests now share the same
  `taminJson` as production instead of a laxer copy.
- **Special cases survived the refactor**: the agent data source still handles
  `ChatTokenExpiredException` explicitly and now maps its own fallback via `toErrorUri()`.
- **The `FeatureNavigation.kt` fix keeps the legacy flag routed** to the objection-insurance
  screen rather than dropping it, and the `:shared` compile break on `develop` is gone.
- No hardcoded user-facing strings and no commented-out code were added.
- **Round 3** (`6cc6b8121`) also fixes two real gaps outside this MR's original scope, both worth
  noting: `TaminServicesScreen`'s disabled-service message was a bare `// TODO display toast` —
  tapping a disabled service silently did nothing; it now shows the server's reason. And
  `ProfileViewModel`'s six-way `merge()` let the first of six independent loads (avatar, identity,
  active relation, …) that failed cancel the other five, so one offline blip could leave the whole
  header stuck on shimmer; each load now fails on its own and only the first failure is toasted
  once instead of up to six times.
