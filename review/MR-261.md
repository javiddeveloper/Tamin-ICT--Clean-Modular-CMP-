## 1. `revokeToken` still swallows cancellation — Medium

**File:** `core/core-network/src/commonMain/kotlin/com/tamin/taminhamrah/dataSource/authSource/AuthRemoteDataSourceImpl.kt:161-174`

```kotlin
override suspend fun revokeToken(accessToken: String?, refreshToken: String?): Boolean {
    logger.d { "revokeToken called. ..." }
    return try {
        userApiService.revokeToken(...)
        true
    } catch (e: Exception) {
        logger.e(e) { "revokeToken API call failed: ${e.message}" }
        false
    }
}
```

Commit `41fbb3c62` reworked `exchangeCodeForTokens`, `refreshTokens` and `signOut` in this exact
file to catch `CancellationException` explicitly and rethrow it before the generic
`catch (e: Exception)` — but `revokeToken`, right below them, still has only the generic catch, so
a coroutine cancelled while `revokeToken` is in flight (e.g. the caller's scope ends during
logout) is swallowed here and reported as a normal `false` return instead of propagating. This
predates this MR (the same shape existed at the merge-base), but is worth flagging now precisely
because the developer was already fixing this exact class of bug for every other function in this
same file in this same round.

**Suggested change:**

```kotlin
} catch (e: CancellationException) {
    throw e
} catch (e: Exception) {
    logger.e(e) { "revokeToken API call failed: ${e.message}" }
    false
}
```
