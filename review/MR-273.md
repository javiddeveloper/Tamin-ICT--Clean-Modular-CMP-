## What was done well

- **This fix directly closes the two paging pitfalls flagged in earlier rounds this cycle**:
  `RetryNextPage` calls `paginator.retry()` (not `loadNext()`, which would be a no-op while the
  paginator still holds an error), and `observePaging()` is guarded by `isObservingPaging` so it
  starts exactly once rather than stacking a new collector on every `LoadRequests`.
- **The legacy double-underlying-collector bug this replaces is well understood and documented**:
  the old `getUserRequests()` flow never completed, and `BaseViewModel`'s `flatMapMerge` (16
  concurrent flows) meant repeated reloads eventually starved every other intent on the screen —
  explained in the code comment, not just fixed silently.
- **`key(state.requests.size) { listState.OnLoadMore(...) }`** correctly re-arms the scroll trigger
  for client-side status-tab filtering, where a whole page can be hidden and leave the scroll
  position already "at the end" with no new event to fire on.
- Reuses the existing `user_requests` cache table with no new Room entity, so no schema/version
  concern here.
