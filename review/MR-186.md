## 1. Debug/scaffold screen shipped as the feature's UI — High

**File:** `feature/workshops/src/commonMain/kotlin/com/tamin/taminhamrah/feature/workshops/ui/WorkshopsScreen.kt`

The entire screen reads as a developer's raw testing scaffold rather than reviewed, user-facing
UI:

- Every string in the file is a hardcoded literal — none of it goes through
  `composeResources/strings.xml`, unlike every other screen in this codebase (rule in
  `docs/vault/Typography.md`). Two of the field labels literally embed the Kotlin variable name in
  parentheses: `"کد کارگاه (workshopId)"` (line 215), `"وضعیت کارگاه (workshopStatus)"` (line 248) —
  that phrasing is not something a designer or copy reviewer would sign off on; it's a
  placeholder label a developer left in while wiring the screen up.
- There's a live, user-visible **"تست دریافت PDF"** ("Test PDF fetch") button (lines 263-268)
  wired to `WorkshopsIntent.TestDownloadPdf`, whose handler
  (`WorkshopsViewModel.kt:59-70`) calls `getRegistrationDeclarationFormUseCase()` purely to toast
  `" ${response.size}"` — a blank-prefixed debug message with no user-meaningful content. This is
  debug/test code left in the shipped screen, the same category this repo's rules call out for
  commented-out code: it should never reach `develop`.
- The screen uses raw Material3 primitives directly (`OutlinedTextField`, `Button`, `Card`,
  `Text`) instead of this project's design-system components
  (`TaminFilledButton`, `TaminTopAppBar`, themed cards, `LocalTaminColors`, etc.) that every other
  feature screen in this codebase uses — no top bar, no back navigation, no visual consistency with
  the rest of the app. `docs/vault/Theme.md`'s rule ("Compose UI must use tokens from
  `core-ui/ui/theme/`. Do not hardcode colors...") is not followed anywhere in this file.
- Several bottom-sheet actions in the workshop-detail sheet are dead ends — e.g. `"نام نویسی
  غیرحضوری بیمه شده"` (line 145-154) only dismisses the sheet with no navigation call, unlike every
  sibling item in the same sheet which calls a `navigateTo...` callback.

**Concrete failure scenario:** if this MR merges as-is, end users reach a screen with English
identifiers leaking into Persian labels, a button whose only purpose is to fetch a PDF and discard
it into a debug toast, and a visual style that doesn't match the rest of the app — the kind of
regression a designer or product reviewer would catch immediately in a build, not something that
needs deep code reading to notice.

**Suggested change:** move all copy into `strings.xml` with real, reviewed Persian text; remove
`TestDownloadPdf` (or move it behind a `docs/vault/`-documented developer-options gate if it's
needed for QA, the same pattern already used elsewhere in this app per
`docs/vault/Feature-Flags.md`); rebuild the screen on the project's existing `core-ui` components;
and either wire up or remove the dead-end bottom-sheet item.

## What was done well

- The province→city→branch cascade-reset logic (`WorkshopsViewModel.handleSelectProvince` /
  `handleSelectCity`) is correct and explicitly documented in a comment, and matches
  `old_android`'s `LocationSelectorWidget` behavior exactly: picking a province clears the
  previously-selected city and branch below it (and their loaded option lists), picking a city
  clears only the branch. `WorkshopsCascadeResetTest.kt` covers this.
- The offline-first caching added to `CityProvinceRepositoryImpl.getProvinces()`/`getCities()` is a
  clean, well-reasoned pattern: emit whatever's cached immediately, then refresh from network, and
  — critically — only propagate the network failure if there was nothing cached to fall back on.
  The comment explaining *why* (`proxy/models/province` returning intermittent 503s, provinces
  rarely changing) is exactly the kind of context that saves the next reader from re-deriving it.
  `CityProvinceRepositoryCacheTest.kt` covers both the cache-hit and cache-miss-then-network paths.
- `TaminBottomSheet`'s new empty-state branch (a `no_items_found` message instead of a blank sheet
  when a picker's filtered list is empty) is a small, safe, broadly-useful fix that goes through
  string resources correctly, unlike the workshops screen.
- Renaming/consolidating `TaminJalaliDatePickerBottomSheet` → `TaminJalaliDatePicker` and
  `IconPosition` → `LoadingButtonIconPosition` was propagated correctly to every existing call
  site (e.g. `OrotezProtezScreen.kt` was updated in the same MR), rather than leaving other
  features on a stale API.
- `ContractsRepositoryBranchesTest.kt` and `ProvinceNameDtoTest.kt` add real coverage for the new
  branch-cache and DTO-mapping paths.
