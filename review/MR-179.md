## 1. Empty pensioner-ID list is silently dropped — High

**File:** `feature/pensioner/src/commonMain/kotlin/com/tamin/taminhamrah/feature/pensionInquiry/ui/edict/EdictViewModel.kt:37-63` (`LoadPensionerIds`)

```kotlin
getPensionerIdUseCase().collect { list ->
    val presentationList = list.toPresentation()
    emit(PartialState.PensionerIdsLoaded(presentationList))
    if (presentationList.isNotEmpty()) { ... }   // nothing happens in the else branch
}
```

Old_android showed an explicit error dialog ("شما بیمه‌شده نیستید" /
`error_active_relation_user_is_insured`) and navigated the user back automatically when this
list came back empty. Here, when it's empty: `isLoading=false`, `hasLoadedOnce` stays `false`,
`edictPensioner` stays `null`. In `EdictContent`/`EdictHeader` neither the skeleton branch
(`!hasLoadedOnce && isLoading`), the data branch (`edict != null`), nor the empty-card branch
(`hasLoadedOnce && !isLoading`) match — the user is left staring at a permanently blank screen
with no explanation and no way out except the back button.

**Suggested change:** on an empty pensioner-ID list, show an error state/dialog and navigate
back, matching old_android's behavior.

> **مغایرت بیزینسی:** اگر کاربر هیچ شناسه مستمری‌بگیری نداشته باشد (یعنی بیمه‌شده/مستمری‌بگیر
> نیست)، در نسخه قدیمی یک پیام خطای واضح («شما بیمه‌شده نیستید») نمایش داده می‌شود و کاربر
> به‌صورت خودکار به صفحه قبل بازمی‌گردد. در نسخه جدید این حالت اصلاً مدیریت نشده و کاربر فقط یک
> صفحه خالی و بدون هیچ توضیحی می‌بیند.

## 2. مرداد ۱۳۹۹ month special-case removed entirely — ➖ rejected

> **Rejected by product/developer (round 2):** this is intentional, not a regression — the
> مرداد ۱۳۹۹ correction edict is no longer relevant; going forward there is exactly one edict
> per year. The leftover hint text (`edict_search_edict_note`) mentioning a possible مرداد
> edict is stale copy and should be updated/removed separately, but the underlying business
> behavior (`MONTH_CODES = listOf("01")`) is correct as shipped.

Original finding, kept for context:

**File:** `feature/pensioner/src/commonMain/kotlin/com/tamin/taminhamrah/feature/pensionInquiry/ui/edict/components/EdictSearchSheet.kt:80`

```kotlin
// Only فروردین edicts are shown. مرداد may be added in a future iteration.
private val MONTH_CODES = listOf("01")
```

Old_android's `getMonthList(is1399)` added a second selectable month (مرداد, code "05")
whenever the chosen year was exactly "1399", and auto-selected the single month when there was
only one option. The new UI hardcodes a single month for every year, so a pensioner whose
supplementary مرداد-1399 edict exists can never view or download it through this screen. The MR
even ships a user-facing note admitting this exists:
`edict_search_edict_note` = *"* حکم مستمری هر سال در فروردین صادر می‌شود و در برخی سال‌ها حکم
اصلاحی مرداد هم صادر می‌گردد."* — the screen tells the user a مرداد edict may exist, with no
way to select it.

**Suggested change:** restore the year-1399 → two-month special case (or confirm with
product/backend that مرداد-1399 edicts are no longer relevant and the note string should be
removed instead).

> **مغایرت بیزینسی:** برای سال ۱۳۹۹، مستمری‌بگیران علاوه بر حکم فروردین، یک حکم اصلاحی مرداد هم
> دارند که باید قابل انتخاب و مشاهده باشد. در نسخه جدید فقط فروردین قابل انتخاب است و امکان
> مشاهده حکم مرداد ۱۳۹۹ به‌کلی حذف شده، حتی با اینکه متن راهنمای همان صفحه به وجود چنین حکمی
> اشاره می‌کند.

## 3. Pensioner-vs-survivor distinction is gone — High

**File:** `feature/pensioner/src/commonMain/kotlin/com/tamin/taminhamrah/feature/pensionInquiry/ui/edict/components/EdictCardComponents.kt:118,349,584`

```kotlin
val info = edict.edictInfo ?: return   // EdictMainCard
val info = edict.edictInfo ?: return   // EdictComparisonCard
val info = edict.edictInfo ?: return   // EdictInfoList (details "info" tab)
```

`EdictPensionerDN.edictInfo` is nullable, and per old_android a survivor-only response can
legitimately arrive with `edictInfo` null/absent-id while `survivorInfo` is populated — that's
exactly how `isPensioner = info.edictInfo?.id != null` used to branch the whole screen: a
different amount label, three-part colored history dates for a pensioner, versus an extra
descriptive paragraph (deceased's father, pension ID, amount before/after increase) for a
survivor. None of that branching exists anymore. When `edictInfo` is null: `EdictMainCard`
returns before drawing its `Card` (blank space where the amount card should be),
`EdictComparisonCard` also renders nothing, and the "اطلاعات حکم" details tab renders nothing —
only the `SurvivorShareCard`s and the breakdown tab show anything. The bottom "download PDF /
send to inbox" bar stays active as if everything loaded normally.

**Suggested change:** reintroduce the pensioner/survivor branch: a distinct amount label and
history-date formatting for pensioners, and the survivor descriptive paragraph (father's name,
pension ID, amount before/after increase) when `edictInfo` is absent but `survivorInfo` is
present.

> **مغایرت بیزینسی:** در نسخه قدیمی، وقتی پاسخ سرویس مربوط به «بازمانده» است (نه خود
> مستمری‌بگیر)، رابط کاربری آگاهانه حالت متفاوتی نشان می‌داد: برچسب مبلغ («مبلغ ناخالص قابل
> پرداخت» به‌جای «مبلغ قابل پرداخت ماهانه») و یک پاراگراف توضیحی مخصوص بازمانده (نام پدر متوفی،
> شناسه مستمری، مبلغ قبل و بعد از افزایش). در نسخه جدید این تشخیص بین «خود مستمری‌بگیر» و
> «بازمانده» به‌کلی حذف شده؛ نتیجه این است که برای پاسخ‌های خالص بازمانده، کارت اصلی مبلغ و کارت
> مقایسه و تب «اطلاعات حکم» همگی خالی نمایش داده می‌شوند و کاربر فقط سهم بازمانده را می‌بیند، بدون
> مبلغ کل حکم یا توضیح مربوط به آن.

## 4. `state.error` is set but never surfaced to the user anywhere — High

**File:** `feature/pensioner/src/commonMain/kotlin/com/tamin/taminhamrah/feature/pensionInquiry/ui/edict/EdictViewModel.kt:201`

`reduceState` sets `error = partialState.message` on every failure path (`LoadPensionerIds`,
`LoadEdict`, `ApplySearch`, `ClearDateFilter`, `RequestSendToInbox`, `DownloadPdf`), but
`EdictUiState.error` is never read anywhere in `EdictScreen.kt` or any of its components —
`EdictEvent` only has `ShowToast`, and nothing ever sends it for these failures. Compare with
the established pattern already in this same module,
`feature/pensioner/.../pensionInquiry/PensionInquiryScreen.kt:45-50`, which does render
`state.error`.

**Failure scenario:** the initial `getPensionerIdUseCase()` call throws — the catch block emits
`PartialState.Error(...)`, `isLoading` becomes `false`, `hasLoadedOnce` stays `false`. The user
sees a blank screen forever with zero feedback and no retry affordance, for any failure on any
of the six intents listed above.

**Suggested change:** either emit an `EdictEvent.ShowToast` from the ViewModel on error, or
render `state.error` in `EdictContent` the way `PensionInquiryScreen.kt` already does.

## 5. Empty edict result shows a generic empty card instead of the old explicit error — Medium (needs confirmation)

**File:** `feature/pensioner/src/commonMain/kotlin/com/tamin/taminhamrah/feature/pensionInquiry/ui/edict/EdictViewModel.kt` (`LoadEdict`/`ApplySearch`/`ClearDateFilter`)

These just do `emit(PartialState.EdictLoaded(edict?.toPresentation()))` with no check that both
`edictInfo` and `survivorInfo` came back null. This is softer than items 1/3/4 since
`EdictEmptyCard` (`edict_empty_title` = "حکمی برای این بازه یافت نشد") does communicate "no
data" — not a silent failure, but a deliberate UX simplification that drops old_android's
explicit `dont_have_edict_info` error-dialog flow.

**Suggested change:** confirm with product whether the empty-card treatment is an intended
replacement for the old error dialog, or whether the dialog should be kept for this specific case.

> **مغایرت بیزینسی:** وقتی برای بازه انتخاب‌شده هیچ اطلاعات حکمی (نه برای خود مستمری‌بگیر و نه
> برای بازمانده) وجود نداشته باشد، نسخه قدیمی یک پیام خطای مشخص نشان می‌دهد. نسخه جدید به‌جای آن
> یک کارت عمومی «حکمی یافت نشد» نمایش می‌دهد؛ رفتار قابل قبول است ولی تفاوت با رفتار قبلی باید
> آگاهانه تایید شود.
