## 1. `CLAUDE.md` deleted and gitignored — High

**Files:** `CLAUDE.md` (deleted, 58 lines), `.gitignore`

```diff
--- a/.gitignore
+++ b/.gitignore
 CLAUDE.local.md
+CLAUDE.md
```

Commit `e1a501b4f` ("chore: stop tracking CLAUDE.md") deletes the file entirely, and a later commit
(`a5f50ccd2`, "...Also ignore CLAUDE.md") adds it to `.gitignore`.

`CLAUDE.md` is the project's own AI-assistant instruction file, checked into the repo — its own first
line of content described it as the project's read-this-first guide (module map, the six "rules that
must not be broken," common build commands). This is different from `CLAUDE.local.md`, which is
already correctly gitignored (personal, per-developer notes, per the existing `.gitignore` entry right
above this diff). This MR appears to conflate the two: `CLAUDE.local.md` is meant to be local-only,
but `CLAUDE.md` is meant to be shared and versioned, the same way any other project documentation is.

If this merges, `develop` (and everyone who pulls it) loses the file, and any future work — including
this same review process, which reads `CLAUDE.md` for the project's rules — loses that shared
reference.

**Suggested change:** revert both changes — restore `CLAUDE.md` and remove the `.gitignore` entry —
unless there's a reason (not evident from the diff or commit message) that this specific file should
stop being shared project documentation.

## 2. Hardware/gesture back bypasses the new abandon confirmation on several screens — High

**Files:** `feature/girlSurvivor/src/commonMain/kotlin/com/tamin/taminhamrah/feature/girlSurvivor/ui/GirlSurvivorScreen.kt`,
`feature/contracts/src/commonMain/kotlin/com/tamin/taminhamrah/feature/contracts/flow/ui/ContractFlowScreen.kt`,
`feature/deferredInstallment/src/commonMain/kotlin/com/tamin/taminhamrah/feature/deferredInstallment/ui/DeferredInstallmentScreen.kt:171-176`

The commit message states the goal plainly: "so users can stay or leave without losing input
silently." Some of the newly-wired screens only trigger `TaminFormAbandonDialog` from the explicit
in-app close (✕) button's `onClick`, with no `BackHandler` at all:

```kotlin
// GirlSurvivorScreen.kt — no BackHandler anywhere in this file
onClick = { showAbandonDialog = true },   // only the ✕ button reaches this
```

```kotlin
// ContractFlowScreen.kt — same shape, no BackHandler
onClick = { showAbandonDialog = true },
```

Pressing the Android system back button or using the back gesture on these two screens does not show
the dialog at all — it exits (and, presumably, discards form state) exactly the way this feature was
built to prevent, just via the other common exit path.

`DeferredInstallmentScreen.kt` does have a `BackHandler`, but only forwards to the new dialog when the
user is *not* on the first step:

```kotlin
// DeferredInstallmentScreen.kt:171-179
val handleBack: () -> Unit = {
    if (uiState.currentStep == DeferredInstallmentStep.CertificateRequest) {
        onBackClicked()   // exits immediately — no abandon dialog
    } else {
        viewModel.sendIntent(DeferredInstallmentIntent.BackToPreviousStep)
    }
}
BackHandler(onBack = handleBack)
```

A user who has filled in the first step and presses back loses that input with no warning, while the
same action from the in-app close button correctly shows the dialog.

For contrast, the screens that route the confirmation through a ViewModel intent rather than pure
local Compose state get this right automatically, because their existing `BackHandler` already fed
into the same intent the close button uses — `DisabilityPensionScreen.kt:147-149`
(`BackHandler { viewModel.sendIntent(DisabilityPensionIntent.CloseClicked) }`, which sets
`showExitConfirmDialog = true` rather than navigating away) and `OccurrenceScreen.kt` are both correct
examples already in this same diff.

**Suggested change:** add a `BackHandler` to `GirlSurvivorScreen`/`ContractFlowScreen` that also sets
`showAbandonDialog = true` (mirroring the ✕ button), and fix `DeferredInstallmentScreen.handleBack` to
show the abandon dialog on the first step too instead of calling `onBackClicked()` directly.

## What was done well

- **The consolidation itself is clean and reduces duplication.** `RetirementDialogs.kt` and
  `DisabilityPensionScreen.kt` both replace a hand-rolled `TaminConfirmationDialog` instance with the
  new shared component, each removing 20-30 lines of near-duplicate dialog-building code with no
  behavior loss (verified both call sites: `onStay`/`onAbandon` map correctly to the previous
  `dismiss`/`confirm` handlers).
- **`TaminFormAbandonDialogCard` is factored out separately from `TaminFormAbandonDialog`** for
  Compose-preview purposes (previews can't host a real `Dialog` window) — a small, sensible bit of
  design rather than working around it with a hack in the preview itself.
- **No hardcoded Persian strings anywhere in the diff** — all dialog text goes through `strings.xml`
  and is interpolated with the per-screen form name (`form_abandon_title`/`_description`), rather than
  needing separate strings per screen.
- **`OccurrenceScreen.kt`'s exit-confirmation trigger logic (`STEPS_REQUIRING_EXIT_CONFIRMATION`,
  the ViewModel-driven dialog visibility) was left untouched** — only the dialog's visual component
  was swapped, correctly preserving the existing (correct) back-button behavior on that screen.
- **All affected modules build and their existing test suites still pass** — no regressions in
  compile or test outcomes from the consolidation itself.
