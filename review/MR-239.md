## 1. `CLAUDE.md` deleted and gitignored — High

**Files:** `CLAUDE.md` (deleted, 58 lines), `.gitignore`

```diff
--- a/.gitignore
+++ b/.gitignore
 CLAUDE.local.md
+CLAUDE.md
```

Commit `e1a501b4f` ("chore: stop tracking CLAUDE.md") deletes the file entirely, and a later commit
(`a5f50ccd2`, "...Also ignore CLAUDE.md") adds it to `.gitignore`.

`CLAUDE.md` is the project's own AI-assistant instruction file, checked into the repo — its own first
line of content described it as the project's read-this-first guide (module map, the six "rules that
must not be broken," common build commands). This is different from `CLAUDE.local.md`, which is
already correctly gitignored (personal, per-developer notes, per the existing `.gitignore` entry right
above this diff). This MR appears to conflate the two: `CLAUDE.local.md` is meant to be local-only,
but `CLAUDE.md` is meant to be shared and versioned, the same way any other project documentation is.

If this merges, `develop` (and everyone who pulls it) loses the file, and any future work — including
this same review process, which reads `CLAUDE.md` for the project's rules — loses that shared
reference.

**Suggested change:** revert both changes — restore `CLAUDE.md` and remove the `.gitignore` entry —
unless there's a reason (not evident from the diff or commit message) that this specific file should
stop being shared project documentation.

> **Round 2 — ✅ fixed, verified** (`5641e7518`). `CLAUDE.md` is restored byte-for-byte (diffed
> against the pre-deletion version — identical), and the `.gitignore` entry is removed.

## 2. Hardware/gesture back bypasses (then over-corrects) abandon confirmation — High

**Files:** `feature/girlSurvivor/.../GirlSurvivorScreen.kt`,
`feature/contracts/.../ContractFlowScreen.kt`,
`feature/deferredInstallment/.../DeferredInstallmentScreen.kt`

### Round 1 finding (context)

Some newly-wired screens only triggered `TaminFormAbandonDialog` from ✕, with no `BackHandler`, so
system back discarded input silently. DeferredInstallment had a `BackHandler` but first-step back
called `onBackClicked()` directly.

Screens that route confirmation through a ViewModel intent already did this right
(`DisabilityPensionScreen`, `OccurrenceScreen`).

### Round 2 fix — partially correct

`5641e7518` fixed **DeferredInstallment** correctly:

```kotlin
val handleBack: () -> Unit = {
    if (uiState.currentStep == DeferredInstallmentStep.CertificateRequest) {
        showAbandonDialog = true
    } else {
        viewModel.sendIntent(DeferredInstallmentIntent.BackToPreviousStep)
    }
}
BackHandler(onBack = handleBack)
```

First step → confirm abandon; later steps → previous step. Matches ✕ on the exit path without
breaking mid-wizard back.

GirlSurvivor / ContractFlow got the simpler (wrong) form:

```kotlin
BackHandler { showAbandonDialog = true }
```

### Round 3 — 🔄 needs rework

**ContractFlowScreen** still has three divergent paths:

| Control | First step | Later step |
|---|---|---|
| ✕ | abandon dialog | abandon dialog |
| Hardware back (`BackHandler`) | abandon dialog | abandon dialog (should step back) |
| Chevron (`handleNavigateBack`) | `onBack()` — **no dialog** | previous step |

```kotlin
// ContractFlowScreen.kt:221
BackHandler { showAbandonDialog = true }

// ContractFlowScreen.kt:245-250 — chevron still uses this
val handleNavigateBack: () -> Unit = {
    when {
        state.isEditMode -> onIntent(ContractFlowIntent.GoToPreviousStep)
        steps.isFirstStep(state.currentStep) -> onBack()   // silent exit
        else -> onIntent(ContractFlowIntent.GoToPreviousStep)
    }
}
```

**GirlSurvivorScreen** same split:

| Control | Details (step 1) | Commitment (step 2) |
|---|---|---|
| ✕ | abandon dialog | abandon dialog |
| Hardware back | abandon dialog | abandon dialog (should `GoToPreviousStep`) |
| Chevron (`onBack`) | `onBack()` — **no dialog** | `GoToPreviousStep` |

```kotlin
// GirlSurvivorScreen.kt:106-109 (passed into content as onBack / chevron)
onBack = {
    if (state.currentStep == GirlSurvivorStep.Details) onBack()
    else viewModel.sendIntent(GirlSurvivorIntent.GoToPreviousStep)
}

// GirlSurvivorScreen.kt:162
BackHandler { showAbandonDialog = true }
```

So round 2 stopped the silent hardware-back exit, but (a) hardware back can no longer step backward
inside the wizard, and (b) the visible chevron on step 1 still discards input with no warning — the
exact failure mode item 2 was opened for.

**Suggested change:** mirror DeferredInstallment on both screens — one shared `handleBack` used by
`BackHandler` **and** the chevron:

- first step → `showAbandonDialog = true`
- later step → existing previous-step intent / navigation
- ✕ can keep always-showing the dialog (abandon whole form)

> **Round 2 — previously marked ✅; superseded by round 3.** DeferredInstallment remains ✅.
> GirlSurvivor + ContractFlow → 🔄 needs rework.
>
> **✅ fixed (post round 3).** Shared `handleBack` / `handleNavigateBack`: first step → dialog;
> later step → previous-step intent; ✕ still always abandons. Chevron + `BackHandler` share it.

```kotlin
BackHandler(onBack = { onIntent(HistoryObjectionStepperIntent.OnBackClicked) })
// top-bar chevron + both bottom-bar chevrons also dispatch OnBackClicked
```

```kotlin
HistoryObjectionStepperIntent.OnBackClicked -> flow {
    val step = uiState.value.currentStep
    if (step == STEP_BRANCH) {
```

**Suggested change:** same DeferredInstallment shape — shared handler for `BackHandler` + chevrons:

- `STEP_BRANCH` → `showAbandonDialog = true` (abandon can keep calling `onNavigateHome()` or
  `NavigateBack` — pick one destination and use it consistently)
- later steps → `OnBackClicked` / step-1 as today

## What was done well

- **The consolidation itself is clean and reduces duplication.** `RetirementDialogs.kt` and
  `DisabilityPensionScreen.kt` both replace a hand-rolled `TaminConfirmationDialog` instance with the
  new shared component, each removing 20-30 lines of near-duplicate dialog-building code with no
  behavior loss (verified both call sites: `onStay`/`onAbandon` map correctly to the previous
  `dismiss`/`confirm` handlers).
- **`TaminFormAbandonDialogCard` is factored out separately from `TaminFormAbandonDialog`** for
  Compose-preview purposes (previews can't host a real `Dialog` window) — a small, sensible bit of
  design rather than working around it with a hack in the preview itself.
- **No hardcoded Persian strings anywhere in the diff** — all dialog text goes through `strings.xml`
  and is interpolated with the per-screen form name (`form_abandon_title`/`_description`), rather than
  needing separate strings per screen.
- **`OccurrenceScreen` / `InspectionScreen` keep step-gated confirmation**
  (`STEPS_REQUIRING_EXIT_CONFIRMATION`) and route hardware back through the existing previous-step
  intent — first step exits without dialog on both ✕ and back by design; later steps confirm on ✕
  and step back on hardware back. Left correctly alone.
- **DeferredInstallment's round-2 back handler is the right template** for the remaining screens.
- **`CLAUDE.md` restoration is clean** (item 1).
