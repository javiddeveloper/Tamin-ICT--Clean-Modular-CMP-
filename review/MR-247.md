## 6. Rowless history flags are still the target of live entry points — High

**Files:**
`shared/src/commonMain/kotlin/com/tamin/taminhamrah/ui/home/HomeViewModel.kt:110`,
`core/core-domain/src/commonMain/kotlin/com/tamin/taminhamrah/deeplink/DeepLinkKey.kt:21-23`,
`core/core-domain/src/commonMain/kotlin/com/tamin/taminhamrah/model/agent/AgentActionKey.kt:160`,
`shared/src/commonMain/kotlin/com/tamin/taminhamrah/ui/navigation/FeatureNavigation.kt:73-78`

```kotlin
// HomeViewModel.kt
is HomeIntent.OnHistorySummaryClick -> handleFeatureClick(FeatureFlag.WAGE_AND_HISTORY)

// DeepLinkKey.kt
MERGE_HISTORY("merge_history", FeatureFlag.MERGE_HISTORY),
WAGE_AND_HISTORY("wage_and_history", FeatureFlag.WAGE_AND_HISTORY),
ALL_HISTORY_INSURANCE("all_history_insurance", FeatureFlag.WAGE_AND_HISTORY),

// AgentActionKey.kt
AgentActionKey.HISTORY_SERVICES_LAST -> FeatureFlag.WAGE_AND_HISTORY
```

This MR removes the menu rows with ids `6` and `7` (`MockMenuData` now has only id `8`, «کلیه سوابق»),
but `MERGE_HISTORY(6)` and `WAGE_AND_HISTORY(7)` stay in the enum and every caller above still points
at them. `featureStatusOf(flag)` reads a flag with no row as `Disabled(null)` (`toFeatureStatus`,
`FeatureStatus.kt:22`), so:

- Tapping the **history-summary card on Home** (added by MR !241, merged into `develop` this morning)
  goes through `handleFeatureClick` → `Disabled` with no message → nothing happens and nothing is
  shown. The `HomeViewModelTest` case at line 360 keeps passing only because it uses a fake
  `FeatureManager` that answers `Enabled` for everything.
- The deep links `merge_history`, `wage_and_history` and `all_history_insurance`, and the assistant's
  `HISTORY_SERVICES_LAST`, are turned down by the same gate.

The comment at `FeatureNavigation.kt:73-76` states this outcome ("the flag gate turns both down until a
row exists again") as if it were acceptable, but most of these callers are live features, not
leftovers. This was not visible in round 1 because the Home card arrived through the `develop` merge
after that round.

> **مغایرت بیزینسی:** در صفحه‌ی اصلی کارت «خلاصه‌ی سوابق» وجود دارد که با لمس آن باید کاربر به صفحه‌ی
> سوابق برود. در این تغییر ردیف منوی «سوابق و دستمزد» حذف شده، ولی همان کارت هنوز به همان ردیف حذف‌شده
> اشاره می‌کند. نتیجه این است که کاربر روی کارت می‌زند و هیچ اتفاقی نمی‌افتد و هیچ پیامی هم نمی‌بیند.
> لینک‌های ورودی برای سوابق (مثل لینک «همه‌ی سوابق بیمه‌ای») و درخواست «آخرین سوابق» از دستیار هوشمند
> هم به همین دلیل بی‌صدا رد می‌شوند.

**Suggested change:** point them at the one history row that exists — `COMBINED_RECORD` — in
`HomeViewModel`, `DeepLinkKey` (all three keys can keep their strings so old links keep resolving) and
`AgentActionKey`. Then `MERGE_HISTORY` and `WAGE_AND_HISTORY` have no caller and can be deleted from the
enum together with their two `navigateToFeature` branches and the «No menu row today» comment.

## 7. `HomeRepositoryImplTest` fails on this branch — Medium

**File:** `core/core-data/src/commonTest/kotlin/com/tamin/taminhamrah/data/repository/home/HomeRepositoryImplTest.kt:302-313`

```
buildQuickAccessEntities tags every row with its own of the 5 chip sections and carries status
java.lang.AssertionError: expected:<HISTORY> but was:<FREQUENT>   (line 312)
```

The test takes `HomeServiceMembership.history.first()` — now `COMBINED_RECORD` — and looks it up with
`entities.find { it.flagId == … }`. Item 1's fix put `COMBINED_RECORD` in `frequent` as well, and the
builder emits one row per group, so the first match is the `FREQUENT` row. The builder is right (a
service may sit in several lists, as the doc on `HomeServiceMembership` says); the test assumed a flag
belongs to one group. This blocks the pipeline.

**Suggested change:** look the row up by flag *and* group, e.g.
`entities.find { it.flagId == historyMember.id && it.group == HomeQuickAccessGroup.HISTORY }`, for both
assertions.

## 9. Reachability of menu-driven entry points is not tested — Low

`FeatureFlagIdsTest` and `MockMenuDataTest` check the two directions "flag → unique" and "row → flag",
but not the third one this MR broke: "every service that a card, deep link or assistant action opens has
a row in the menu". Item 6 is exactly that hole, and it would have failed a test with one line of
setup.

> **سناریوی بیزینسی:** اگر سرویسی از منو حذف یا ادغام شود ولی کارتی در صفحه‌ی اصلی، یک لینک ورودی یا
> یک دستور دستیار هوشمند هنوز به آن اشاره کند، کاربر فقط می‌بیند که «لمس می‌کنم و هیچ اتفاقی نمی‌افتد».
> تستی نیست که از این وضعیت جلوگیری کند.

**Suggested change:** one test that walks every `DeepLinkKey` and every `AgentActionKey` flag mapping
(plus the flags the home screen taps) against `mockMenuData` and fails on any flag with no row.
