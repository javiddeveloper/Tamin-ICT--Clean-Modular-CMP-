## 8. Housekeeping left over — Low

Of the three parts of the round-2 item, the version comment is now a single line and `Database.md` is
updated. Still open:

1. **`5.json` is not committed.** `core/core-database/schemas/com.tamin.taminhamrah.data.local.TaminXDatabase/`
   still holds `1.json`, `3.json`, `4.json`. `Database.md:40` now says "the active schema is currently at
   `TaminXDatabase/5.json`" and that the file "must be committed", so the doc points at a file the
   repository does not have. Building any module that uses `core-database` generates it as an untracked
   file.
2. **`docs/vault/Glossary.md:27`** lists `MERGE_HISTORY` as the flag for «سوابق تلفیقی» — a flag this MR
   deletes.
3. **`FeatureEntryPointReachabilityTest.kt:15`** ends "see MR !247 review, item 6". Review reports are not
   kept on `develop`, so the pointer will lead nowhere after the merge. (Same reason the version comment
   was shortened.) The line also writes `[FeatureFlag.Disabled]`; the type is `FeatureStatus.Disabled`.

**Suggested change:** commit `5.json`, point the Glossary row at `COMBINED_RECORD` (or drop the flag name),
and drop the review pointer from the test's doc comment.

## What was done well

- **The round-1 concern about ids was resolved in the right direction**: returning to the server's
  numbers and using `sorting` for order keeps the mock and the real menu interchangeable, and the
  comment on `FeatureFlag` explains the gaps in the numbering.
- **Every round-1 item got a real fix, not a workaround** — including tests for the DAO behaviour that
  exercise the real clear-then-insert body through a state-backed fake.
- **The database bump is the cheaper option**: one destructive migration instead of hand-migrating
  cached `flagId`s.
- **The new reachability test fails for the right reason**: aimed at a flag with no row it names the entry
  point and the flag, so the next person to remove a menu row is told exactly what still points at it.
- **The branch already merged `develop`**, so it goes into the target with no conflict.
