## 1. Loan/installment deduction items (`clpType == "3"`) are completely dropped from the payroll breakdown — High

**File:** `feature/pensioner/src/commonMain/kotlin/com/tamin/taminhamrah/feature/pensionInquiry/ui/payroll/components/PayRollCardComponents.kt:77-78, 112-113, 329-330`

```kotlin
private const val CLP_TYPE_PAYMENT = "1"
private const val CLP_TYPE_DEDUCTION = "2"
...
val paidTotal = items.filter { it.clpType == CLP_TYPE_PAYMENT }.sumOf { it.sumAmount }
val deductionTotal = items.filter { it.clpType == CLP_TYPE_DEDUCTION }.sumOf { it.sumAmount }
...
val payments = items.filter { it.clpType == CLP_TYPE_PAYMENT }
val deductions = items.filter { it.clpType == CLP_TYPE_DEDUCTION }
```

> در نسخه‌ی قدیمی (`old_android/.../PayRollResponse.kt`)، ردیف‌های فیش حقوقی بر اساس `clpType` به **سه** دسته تقسیم می‌شدند:
> - `clpType == "1"` → «پرداختی‌ها»
> - `clpType == "2"` → «کسورات» (بیمه و ...)
> - `clpType == "3"` → **«مانده اقساط وام»** — یک بخش جداگانه که فقط وقتی نمایش داده می‌شد که آیتمی از این نوع در فیش وجود داشت.
>
> در کد جدید، هیچ‌جا `clpType == "3"` بررسی نمی‌شود — فقط دو ثابت `CLP_TYPE_PAYMENT` و `CLP_TYPE_DEDUCTION` وجود دارند و آیتم‌های نوع سوم نه در «پرداخت‌های انجام‌شده» قرار می‌گیرند، نه در «کسر پرداخت»، و در هیچ بخشی از UI نمایش داده نمی‌شوند. یعنی برای کاربری که وام دارد و قسط آن از حقوقش کسر می‌شود، این کسورات به‌طور کامل از فیش حقوقی محو می‌شوند و کاربر نمی‌فهمد چرا مبلغ خالص دریافتی‌اش کمتر شده است.

Note: this MR also introduces `payroll_deductions_section_title`/`payroll_payments_section_title` string resources but no equivalent `payroll_loan_section_title` — so it's not just a missed filter, there's no UI slot for this category at all yet.

**Suggested change:** add a third `CLP_TYPE_LOAN = "3"` bucket (mirroring `old_android`'s `getLoanList`), a corresponding section title resource, and render it as a third optional section — shown only when present, matching `old_android`'s conditional `detailInfo[...]` population.

## 2. Hardcoded error message duplicated instead of reusing the existing string resource — High

**File:** `feature/pensioner/src/commonMain/kotlin/com/tamin/taminhamrah/feature/pensionInquiry/ui/payroll/PayRollViewModel.kt:85, 125`

```kotlin
if (pensionerId.isNullOrEmpty()) {
    emit(PartialState.Error("شناسه مستمری‌بگیر یافت نشد"))
    return@flow
}
```

This exact Persian literal already exists as `Res.string.error_empty_pensioner_id` in `core/core-ui/.../composeResources/values/strings.xml:11`, and is already used correctly elsewhere in the codebase (`PensionStatusInquiryViewModel.kt`). Per `CLAUDE.local.md` rule 7, user-facing Persian text must come from `strings.xml`, not be a literal in code — and here the resource this exact message needs already exists, so the fix is a one-line change, not new infrastructure.

(The same hardcoded literal also exists in the pre-existing `EdictViewModel.kt:82`, outside this MR's diff — worth a follow-up cleanup there too, but not blocking for this MR.)

**Suggested change:** replace both occurrences with `getString(Res.string.error_empty_pensioner_id)`.

## 3. Payroll search date picker allows selecting up to 5 years in the future — Medium

**File:** `core/core-ui/src/commonMain/kotlin/com/tamin/taminhamrah/ui/components/TaminJalaliDatePicker.kt:74, 263` (new `TaminJalaliMonthYearPickerBottomSheet`, added in this MR and used only by `PayRollSearchSheet.kt`)

```kotlin
private const val YEARS_AHEAD = 5
...
val lastYear = remember { PersianDateFormatter.currentJalaliYear() + YEARS_AHEAD }
val years = remember(lastYear) {
    (FIRST_YEAR..lastYear).map { it.toString().toPersianDigits() }.toImmutableList()
}
```

> در نسخه‌ی قدیمی (`old_android/.../PensionerPayRollFragment.kt`)، ورودی سال جست‌وجوی فیش حقوقی صراحتاً محدود به سال جاری بود: اگر کاربر سالی بزرگ‌تر از سال جاری شمسی وارد می‌کرد، مقدار به‌صورت خودکار به سال جاری اصلاح می‌شد (چون فیش حقوقی برای ماه/سالی که هنوز فرا نرسیده وجود ندارد).
>
> در کد جدید، ویجت انتخاب ماه/سال برای جست‌وجوی فیش حقوقی تا ۵ سال بعد از سال جاری را هم در چرخ انتخاب سال نشان می‌دهد و هیچ محدودیتی روی انتخاب ماه/سال آینده (حتی در همان سال جاری) اعمال نمی‌شود. کاربر می‌تواند بازه‌ای را انتخاب کند که هنوز فیشی برایش صادر نشده — که فقط به نتیجه‌ی «فیشی یافت نشد» منجر می‌شود، اما این با رفتار قبلی که اصلاً اجازه‌ی چنین انتخابی را نمی‌داد متفاوت است.

This is a shared component built specifically for this feature (its only current caller is `PayRollSearchSheet`), so restricting it here has no blast radius on other screens.

**Suggested change:** either cap the year wheel at `currentJalaliYear()` (no `YEARS_AHEAD` for this call site) and additionally disable months after the current month when the selected year equals the current year, or pass an optional `maxYear`/`maxMonth` parameter to `TaminJalaliMonthYearPickerBottomSheet` so future callers that do need forward dates aren't affected.
