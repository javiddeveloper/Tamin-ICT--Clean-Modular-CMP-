## 1. Rules bottom sheet hardcoded to student content — High

**File:** `core/core-ui/src/commonMain/kotlin/com/tamin/taminhamrah/ui/contractFlow/ContractRulesBottomSheet.kt`

```kotlin
fun ContractRulesBottomSheet(
    onDismiss: () -> Unit,
    title: String = stringResource(Res.string.contract_rules_sheet_title_student),
    ...
) {
    ...
    Text(text = stringResource(Res.string.contract_rules_sheet_student_p1), ...)
    // section1_item1..4, section2_item1..3 — every string is `..._student_...`
```

Every default parameter and every body string in this component is student-specific, and
`strings.xml` has no `contract_rules_sheet_freelance_*` entries at all. `ContractFlowScreen.kt`
(shared by every `ContractFlowConfig`) calls it with no arguments:

```kotlin
if (showRulesSheet) { ContractRulesBottomSheet(onDismiss = { showRulesSheet = false }) }
```

`FreelanceContractFlowConfig.rulesPdfPath = "rules.pdf"` correctly matches
`InsuranceContractFragment`'s legacy rules document — but the actual composable never reads it. A
freelance applicant who taps «قوانین» during this MR's own new flow will be shown the *student*
insurance eligibility rules (age 18–50, student-certificate requirement) — legal text for a
contract they are not signing, in the flow this MR is specifically about enabling.

**Suggested change:** parameterise the sheet by `ContractFlowConfig` (or pass explicit string
resources), the same way `screenTitleRes`/`insuranceTypeLabelRes` already are, and add the
freelance-specific `strings.xml` entries before this ships. (Filed identically against MR !213,
since it is the same shared file — whichever of the two fixes it first, the other should just pick
up the fix on the next merge from `develop` rather than re-doing it.)

## 3. `ContractFlowViewModel` has no tests — Medium

**File:** `feature/contracts/src/commonMain/kotlin/com/tamin/taminhamrah/feature/contracts/flow/ui/ContractFlowViewModel.kt` (1,221 lines)

The only test in `:feature:contracts` is `ContractPreflightGateTest.kt` — the eligibility gate.
Nothing exercises the ViewModel itself, which is what this MR most substantially grows: it now
carries the free-job branching this review just verified against `old_android` (previous section) —
day-limit + eligibility-service checks for «هلال احمر», a separate status check for «دانشجوی
پزشکی», each locking the premium rate and disabling online payment on success — plus premium-range
selection, file-upload validation, step navigation, and submit handling, all shared across four
contract types.

> **سناریوهای بیزینسی جاافتاده:** دقیقاً همان دو سناریویی که این ریویو به‌صورت دستی با کد قدیمی
> مقایسه کرد و درست از آب درآمد، هیچ تستی محافظتشان نمی‌کند: انتخاب شغل «هلال احمر» باید هم محدودیت
> روز ۲۰ ام را رعایت کند و هم وضعیت صلاحیت را از سرویس بگیرد و در صورت رد هرکدام کاربر نتواند ادامه
> دهد؛ انتخاب شغل «دانشجوی پزشکی» باید وضعیت را جداگانه از سرویس بگیرد و رد شود اگر مجاز نباشد. یک
> تغییر بعدی در این فایل مشترک می‌تواند این دو قاعده را بدون هیچ هشداری خراب کند — همان‌طور که این
> ریویو مجبور شد آن‌ها را دستی، خط‌به‌خط با نسخهٔ قدیمی مقایسه کند تا مطمئن شود درست پیاده شده‌اند.

Given this flow is meant to go live for freelance applicants, this is the point where the two rules
just verified stop being "probably fine" and become something a future change could silently break.

**Suggested change:** at minimum, one success/one rejection test for each of the two special-job
branches, plus the submit success/failure paths — `ContractPreflightGateTest.kt`'s structure and
`FakeContractsRepository` are a ready starting point.

## What was done well

- **The two money-sensitive special-job rules were ported exactly**, not approximately: same job
  codes (`"113798"`/`"110977"`), same day threshold (`> 20`), same side effects (locked premium
  rate, hidden slider, payment disabled) as `InsuranceContractFragment`/`EditContractFragment`. This
  is the kind of detail that's easy to get subtly wrong (off-by-one on the day, wrong premium rate
  constant) and it wasn't.
- **`FreeJobWagesPaging` shipped with its own test** (`FreeJobWagesPagingTest.kt`, 73 lines) —
  unlike the ViewModel as a whole, this new paging model for free-job wage lookups wasn't left
  uncovered.
- **The legacy `rules.pdf` split is preserved** in `FreelanceContractFlowConfig.rulesPdfPath`, even
  though (item 1) it isn't wired through to the sheet that should read it yet.
- **`GetOptionalPremiumRangeUseCase`/`CheckRedCrossStatusUseCase`/`CheckMedicalStudentUseCase`** are
  registered in `DomainModule` correctly, and the retired `MakeFreelanceContractUseCase` was removed
  cleanly (use case, DI registration, and its dedicated test all together) in favour of the
  generalised `MakeContractUseCase` — `grep` finds no orphaned references.
- **`:feature:studentInsuranceContract` was fully removed** alongside the new flow, with
  `settings.gradle.kts`, `shared/build.gradle.kts`, `Koin.kt`, and navigation all updated together.
