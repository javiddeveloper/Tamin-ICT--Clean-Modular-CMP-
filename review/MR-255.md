## 1. `DetailRow` loses its whole-row tap-to-copy target when `copyAsChip = true` — Low

**File:** `core/core-ui/src/commonMain/kotlin/com/tamin/taminhamrah/ui/components/TaminPrimitives.kt:509-519`

```kotlin
/** Draws a [copyValue] row's value as a [CopyCodeChip] instead of a glyph beside plain text. */
copyAsChip: Boolean = false,
) {
    val chipCopy = if (copyAsChip && copyValue != null) rememberCopyAction(copyValue, announce = false) else null
    val copy = if (chipCopy == null) copyValue?.let { rememberCopyAction(it) } else null
    ...
    Row(
        modifier = modifier
            .fillMaxWidth()
            .then(if (copy != null) Modifier.clickable(onClick = copy) else Modifier)
            ...
```

When `copyAsChip = true`, `chipCopy` is non-null, so `copy` is always `null` — the whole-row
`clickable` is never applied. Before this MR's `CopyCodeChip` extraction, the doc comment right
above this function (still present, now stale) explains the original intent: *"The whole row is
the target, not the glyph — the glyph is 16dp and a poor thing to aim at."* `RecordDetailComponents.kt`'s
`RecordSummaryCard` uses `copyAsChip = true` for the tracking-code row, so on that screen only the
small `CopyCodeChip` itself is now tappable, not the row — a real, if minor, shrink of the copy
touch target, contradicting the function's own documented rationale.

**Suggested change:** keep the row itself clickable in the `copyAsChip` case too (invoke `chipCopy`
from the row's `clickable`, not only from the chip), or update the doc comment if the smaller
target is intentional going forward.

## What was done well

- **The MedicalConfirmations list/detail split preserves every action.** The new nested nav graph
  (`MedicalConfirmationsList` → `MedicalConfirmationDetail(listKey)`) shares one ViewModel via
  `backStackEntry.sharedViewModel`; the row is looked up from the already-loaded list by `listKey`
  and auto-pops if not found (e.g. after process death) instead of showing an empty screen.
  Open-certificate, send-to-inbox, the "saved to inbox" dialog, and PDF download/dismiss intents are
  all wired identically in the extracted `MedicalConfirmationDetailScreen.kt`.
- **`PdfSaver`'s expect/actual signature change is consistent.** `save()`'s return type changed from
  `Unit` to `String?` and both the Android and iOS actuals were updated identically; `TaminPdfViewer.kt`'s
  new toast on the returned message is purely additive, the existing OS notification and
  download-to-device behavior are unchanged.
- **All 7 `CopyCodeChip` call sites copy the correct value** — no wrong-field copies found across
  `RecordCard`, `InfoChip`, `HistoryDurationCard`, `WorkshopListComponents`,
  `HistoryObjectionScreen`, and `RecordDetailComponents`.
- **`RecordSearchSheet.kt`'s button reorder is cosmetic only** — Apply/Clear swapped position with
  no change to either button's `onClick` or validation logic.
