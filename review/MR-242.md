## 1. `CancellationException` swallowed at multiple sites — High

**Files:** `feature/objectionInsurance/src/commonMain/kotlin/com/tamin/taminhamrah/feature/objectionInsurance/ui/ObjectionInsuranceViewModel.kt:140,161`,
`core/core-network/src/commonMain/kotlin/com/tamin/taminhamrah/dataSource/objectionInsurance/ObjectionInsuranceRemoteDataSourceImpl.kt:37,61`

```kotlin
// ObjectionInsuranceViewModel.kt:130-144
private fun loadData(): Flow<PartialState> = flow {
    emit(PartialState.Loading(true))
    try {
        val hasActiveRequest = checkStatusConflictUseCase().first()
        ...
    } catch (e: Exception) {
        emit(PartialState.Error(e.toSingleLineMessage()))
    }
    emit(PartialState.Loading(false))
}
```

Both `loadData()` and `handleSubmitConfirmed()` catch broadly with no `CancellationException`
rethrow first. The same shape repeats in the remote data source's shared `fetchData` helper (used
by `checkStatusConflict`, `getConflictHistories`, `confirmConflict`, `finalConfirmConflict`) and in
`saveConflict`'s own try/catch:

```kotlin
// ObjectionInsuranceRemoteDataSourceImpl.kt:56-65
private suspend fun <T> fetchData(call: suspend () -> BaseDTO<T>): T {
    return try {
        call().extractData()
    } catch (e: TaminErrorUriException) {
        throw errorParser.parseGeneralError(e)
    } catch (e: Exception) {
        throw errorParser.parseGeneralError(TaminErrorUriException(ErrorUri.NO_CONNECTION_ERROR))
    }
}
```

A user who navigates away from the screen mid-request has that cancellation caught and converted
into a state update / a relabeled `NO_CONNECTION_ERROR` instead of propagating normally, breaking
structured concurrency — the same bug already found and fixed in several sibling MRs this cycle
(e.g. `ContractPremiumPaymentViewModel`, `DastmozdInfosAgentService`).

**Suggested change:** add `catch (e: CancellationException) { throw e }` before the general catch
at both ViewModel sites and both data-source sites (the `fetchData` fix covers 4 of the 5 repository
methods at once).
