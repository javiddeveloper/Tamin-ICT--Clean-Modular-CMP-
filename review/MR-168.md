## 1. Refund amount (`payPrice`) no longer shown anywhere on the certificate card — High

**File:** `feature/treatment/src/commonMain/kotlin/com/tamin/taminhamrah/feature/treatment/ui/components/TreatmentCostsComponents.kt:189-251`

Before this MR, `CertificateCard` rendered `item.payPrice` as the card's headline value:

```kotlin
// removed by this MR
NumericText(
    text = item.payPrice.toLongOrNull()?.toPriceFormat() ?: ABSENT_VALUE,
    style = MaterialTheme.typography.titleMedium,
    color = accent,
)
```

In the rewritten `CertificateCard` (lines 189-251), `item.payPrice` is never referenced anywhere — not in the collapsed header, not in any `DetailRow`/`DetailPillRow` in the details block. `payPrice` is now fully unused in this file.

A user opens "بازپرداخت هزینه‌های درمان" to check how much was refunded for a claim. The card shows status, dates, national code, center name, and two payment sub-fields (`payService`, `payOtherService`), but never the actual refund total. The only way to see the number is to download/open the PDF certificate — a regression from current production behaviour.

**Suggested change:** Reintroduce `item.payPrice` in the new layout — e.g. as a `DetailPillRow`, or resurfaced in `RecordCard`'s existing header slots if the design allows.

> **مغایرت بیزینسی:** در نسخه‌ی قبلی این صفحه، مبلغ واقعی بازپرداخت هزینه‌ی درمان (مهم‌ترین عددی که کاربر برای بررسی هر پرونده دنبالش می‌گردد) روی کارت نمایش داده می‌شد. در پیاده‌سازی جدید این مقدار به‌طور کامل از رابط کاربری حذف شده و کاربر دیگر هیچ‌جا — نه در حالت جمع‌شده و نه در جزئیات باز شده — نمی‌تواند مبلغ بازپرداخت را ببیند، مگر اینکه فایل PDF سند را دانلود و باز کند.

## 2. Actions menu offered even for certificates never issued (`repId` absent) — High

**File:** `feature/treatment/src/commonMain/kotlin/com/tamin/taminhamrah/feature/treatment/ui/components/TreatmentCostsComponents.kt:177-209`

```kotlin
val actions = remember(viewLabel, sendLabel) {
    persistentListOf(
        ActionMenuItem(CostsAction.VIEW_CERTIFICATE, viewLabel, Res.drawable.ic_tamin_eye),
        ActionMenuItem(CostsAction.SEND_TO_INBOX, sendLabel, Res.drawable.ic_email),
    )
}
...
onActionSelect = { action ->
    when (action) {
        CostsAction.VIEW_CERTIFICATE -> onOpenCertificate(item.repId)
        CostsAction.SEND_TO_INBOX -> onSendToInbox(item.repId)
    }
},
```

The codebase already has a rule for this exact case, in `CertificateStatus.kt` (untouched by this MR, but now dead):

```kotlin
/** A certificate that was never issued comes back with this id; there is nothing to act on. */
private const val ABSENT_REP_ID = "0"
...
val TreatmentCostPR.isActionable: Boolean
    get() = repId.isNotBlank() && repId != ABSENT_REP_ID
```

`isActionable` has zero usages in `feature/treatment` after this MR. The pre-MR `CertificateCard` only rendered the two action buttons `if (actionable)`. The rewritten card always shows the operations button/menu, with no `isActionable` gate. `old_android`'s `TreatmentCostsFragment.kt` enforces the same rule explicitly, even at the click-handling level:

```kotlin
if (item.repId!=0 && item.repId!=null) {
    showDialog(id = item.repId)
} else {
    showAlertDialog(MessageOfRequestDialogFragment.MessageType.ERROR, getString(R.string.error_recive_data))
}
```

A refund record with `repId == "0"` (not yet issued by the service) is rendered like any other row. The user taps «عملیات» → «مشاهده سند» / «ارسال به صندوق»; `onOpenCertificate("0")` / `onSendToInbox("0")` fire a request with an invalid id, which will either fail silently or surface a raw/unfriendly API error, instead of the old app's explicit error guard.

**Suggested change:** Gate the actions on `item.isActionable` again — either hide the operations button/menu entirely when not actionable, or keep it visible but short-circuit `onActionSelect` with the old error message when `!item.isActionable`.

> **مغایرت بیزینسی:** در نسخه‌ی قبل، برای پرونده‌هایی که هنوز توسط سرویس صادر نشده‌اند (شماره سند نامعتبر/خالی است)، گزینه‌های «مشاهده سند» و «ارسال به صندوق» اصلاً در اختیار کاربر قرار نمی‌گرفت، چون اقدام روی چنین پرونده‌ای باعث ارسال یک درخواست نامعتبر به سرور می‌شد. در کد جدید این بررسی به‌طور کامل حذف شده و منوی عملیات برای همه‌ی ردیف‌ها — حتی پرونده‌های صادرنشده — همیشه فعال و در دسترس است.

## 3. "تاریخ پذیرش" (admission date) row dropped from certificate details — Medium

**File:** `feature/treatment/src/commonMain/kotlin/com/tamin/taminhamrah/feature/treatment/ui/components/TreatmentCostsComponents.kt:215-251`

Removed by this MR:

```kotlin
DetailRow(label = stringResource(Res.string.costs_admission_date), value = item.datePaz, valueColor = colors.blueText)
```

`item.datePaz` (admission date) is not shown anywhere else in the new detail list. `old_android`'s equivalent (`detailTreatmentCostInfo()` → `label_date_reception` / `datePaz`) keeps this field. `strings.xml` still defines `costs_admission_date` but it is now unused anywhere in the codebase.

A user expanding a certificate's details to check when the treatment/admission took place can no longer find that date on the card — only the refund's estimated payment date is shown.

**Suggested change:** Re-add a `DetailRow` for `item.datePaz` using `Res.string.costs_admission_date`.

## 4. `payService` relabeled ("پروتز" → "پرونده") and zero-amount muted styling lost — Medium

**File:** `feature/treatment/src/commonMain/kotlin/com/tamin/taminhamrah/feature/treatment/ui/components/TreatmentCostsComponents.kt:243-250`

```kotlin
DetailRow(
    label = stringResource(Res.string.costs_file_payment),   // "پرداختی پرونده"
    value = item.payService.toRialAmount(ABSENT_VALUE),
)
DetailPillRow(
    label = stringResource(Res.string.costs_other_services_payment),
    amount = item.payOtherService.toRialAmount(ABSENT_VALUE),   // always rendered in a bright green pill
)
```

Removed:

```kotlin
StatTile(
    label = stringResource(Res.string.costs_prosthesis_payment),   // "پرداختی پروتز"
    amount = item.payService.toRialAmount(ABSENT_VALUE),
    containerColor = colors.blueBg,
    contentColor = if (item.payService != NO_AMOUNT) colors.blueText else colors.textMuted,
    ...
)
```

`old_android`'s `TreatmentCostsExpensesResponse.detailTreatmentCostInfo()` names this exact field `label_prosthesis_payment_title` and colors it only "if (payService != "0")" — confirming `payService` means "prosthesis payment," not "file payment," and that the zero-vs-nonzero color distinction is intentional old business behaviour. Both pieces are gone: the label now says "پرداختی پرونده" instead of "پرداختی پروتز", and `DetailPillRow`/`DetailRow` no longer distinguish a real amount from "0" — a `payOtherService` of `"0"` still renders in the same bright-green pill as a real amount.

A certificate where the service reports `payOtherService = "0"` shows a highlighted green pill "۰ ریال", reading as "zero rial was paid to me" with the same visual weight as an actual payment, instead of the previous muted/neutral treatment signalling "nothing to report here."

**Suggested change:** Use `Res.string.costs_prosthesis_payment` (or confirm the rename is intentional — but if so it needs business sign-off, not a silent rename), and reinstate a muted/neutral color when the amount equals `NO_AMOUNT`.

> **مغایرت بیزینسی:** فیلد «پرداختی پروتز» (مبلغی که بابت پروتز پرداخت شده) در نسخه‌ی جدید با عنوان «پرداختی پرونده» نمایش داده می‌شود که معنای متفاوتی دارد و ممکن است کاربر را در تشخیص نوع پرداخت گمراه کند. علاوه‌براین، وقتی سرویس مبلغ پرداختی را صفر گزارش می‌کند، قبلاً این مقدار با رنگ کم‌رنگ/خنثی نمایش داده می‌شد تا مشخص باشد چیزی پرداخت نشده؛ در طراحی جدید همان مقدار صفر داخل یک برچسب سبزرنگ برجسته نمایش داده می‌شود، انگار پرداختی واقعی انجام شده است.

## What was done well

- **Real de-duplication, not a refactor for its own sake.** `RecordCard`/`RecordCardParts` in `core/core-ui` consolidate two near-identical, hand-maintained card implementations (`InboxItemCard`, `CertificateCard`) into one shared, documented component — exactly the reuse-first rule in `CLAUDE.md` (rule 5), and a genuine ~380-line net reduction in `InboxItemCard.kt` alone.
- **Doc comments earn their keep.** Comments in `RecordCard.kt`/`RecordCardParts.kt`/`TreatmentDimens.kt` explain *why* (e.g. rail-at-physical-right rationale, `Animatable` vs `State` choice for the stamp, `LazyRow` → scrolling `Row` for `PageIndicator`) rather than restating the code. No commented-out code was found in this diff.
- **A real bug fix bundled in.** `CertificateList`'s `when` block now handles `error != null` as its own branch (`CostsErrorState`) before falling through to empty/list branches. Previously an error with an empty list fell into `else -> itemsIndexed(...)` and rendered nothing — no error UI was ever shown. This MR fixes that silently-swallowed-error case.
- **Small correctness improvements alongside the visual work.** Keying `expanded`/`isExpanded` state on the item id (`remember(item.repId)`, `remember(item.id)`) fixes state bleed-through when `LazyColumn` recycles composables across scroll.
