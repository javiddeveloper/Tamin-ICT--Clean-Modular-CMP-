## 2. Internal hosts ship in release, and overrides apply in release — High

**Files:** `feature/developerOptions/.../ui/model/BaseUrlPresets.kt:32-48` ·
`core/core-datastore/.../DeveloperOptionsRepositoryImpl.kt:22`

Two things are gated by `AppConfig.isDebug` and two things are not.

**Gated:** the profile menu entry (`ProfileScreen.kt:670`). Good — that is the right check and the
right place for the entry point.

**Not gated — (a) the preset list is compiled into every build.** `:feature:developerOptions` is an
unconditional `api(project(...))` dependency of `:shared`, so `BaseUrlPresets` and its string
constants land in the release APK/IPA:

```kotlin
BaseUrlPreset("Test", "https://eservices.test.org:9090/api/")
BaseUrlPreset("Test", "https://account-test.tamin.ir:9090/auth/")
BaseUrlPreset("Old Android Test", "http://s-naghavi.tamin.org:7002/auth/")
BaseUrlPreset("پرونده سلامت من", "http://172.16.14.115:5700/api/")
BaseUrlPreset("Dev IP", "http://172.16.15.54:9001/")
```

Anyone who unzips the published app gets a list of the organisation's internal auth/test hostnames,
a named internal machine, and two private-range IPs with ports. For a سازمان تأمین اجتماعی app this
is information the app should not be handing out, and it is exactly the kind of thing a security
review of a release build flags.

**Not gated — (b) the override itself is honoured in release.**
`DeveloperOptionsRepositoryImpl.getEffectiveBaseUrl` returns whatever is in `Settings`, with no build-type
check, and *every* client now resolves through it — the main and auth `HttpClient`s, the health
Ktorfit, the AI client, `AuthAuthorizeUrlUseCaseImpl`, `GetSignOutUrlUseCase`, and all four
`AuthRemoteDataSourceImpl` token/signout/revoke URLs. So if the `dev_opt_base_url_*` keys are ever
written on a device by any other means (a restored backup, an unencrypted shared-prefs file on a
rooted device, a future code path), a **production** build will send OAuth codes, refresh tokens and
API traffic to that host, and nothing in the app would show it.

**Suggested change:** make both facts follow from one guard rather than from a UI check:

```kotlin
override fun getEffectiveBaseUrl(key: BaseUrlKey): String =
    if (AppConfig.isDebug) _overrides.value[key] ?: key.defaultValue else key.defaultValue
```

and keep the preset table out of release builds — either move `:feature:developerOptions` behind a
debug-only source set / flavour dependency, or (simplest) move the preset URLs into `debug`-only
`BuildConfig`/source-set constants so the release binary never contains them. If the module must stay
in every build, the route registration in `TaminHamrahNavGraph.kt:525` should be inside the same
`AppConfig.isDebug` check as the menu item, so no navigation path reaches the screen in release.

## 3. Overridden URLs are concatenated without normalising the trailing slash — Medium

**Files:** `DeveloperOptionsRepositoryImpl.kt:22` and every consumer, e.g.
`AuthRemoteDataSourceImpl.kt:27`

```kotlin
val url = "${developerOptionsRepository.getEffectiveBaseUrl(BaseUrlKey.ACCOUNT)}server/v2/token"
```

Every default value ends with `/` (`https://account.tamin.ir/auth/`), and all five ACCOUNT consumers
build their URL by direct string concatenation. The screen accepts free text
(`developer_options_custom_url_hint` — «آدرس دلخواه (IP یا دامنه)») with no validation and no
normalisation, so typing `https://account-test.tamin.ir:9090/auth` — the same URL minus one
character — produces:

```
https://account-test.tamin.ir:9090/authserver/v2/token
```

The request fails with a generic network error and nothing points at the missing slash. The same
applies to MAIN/AI/HEALTH_PROFILE via `url(baseUrl)` in `defaultRequest` and `Ktorfit.baseUrl(...)`,
where Ktorfit additionally *requires* a trailing slash and will throw at client-construction time —
i.e. at Koin graph creation, which surfaces as a crash on next launch rather than as a bad request.

It is recoverable (the reset button is there), but the failure gives the developer no clue, and on
the Ktorfit path it takes the app down at startup.

**Suggested change:** normalise once, where the value is stored or read:

```kotlin
override fun setOverride(key: BaseUrlKey, url: String) {
    val normalized = url.trim().let { if (it.endsWith("/")) it else "$it/" }
    …
}
```

and reject a value that has no `http://` / `https://` scheme before saving it.

## 4. No tests for the override repository or for `extractTypedData` — Medium

**Files:** `core/core-datastore/.../DeveloperOptionsRepositoryImpl.kt` ·
`core/core-network/.../tools/BaseDTO.kt`

The MR adds no tests. Two pieces here are worth pinning down, both because they are pure logic with
no UI and because a regression in either is invisible until it reaches a user:

> **سناریوهای جاافتاده:**
>
> - **`extractTypedData` — پیام خطای دروازه باید به کاربر برسد.** کل هدف کامیت دوم این است که وقتی
>   سرویس تغییر شمارهٔ همراه خطا برمی‌گرداند، متن خطای خودِ سرویس (مثلاً «شماره وارد شده متعلق به شما
>   نیست») به کاربر نشان داده شود، نه یک پیام عمومی. سه حالت باید تست شود: پاسخ موفق که درست
>   دیسریالایز می‌شود، پاسخ خطای ۴۰۰ که `data` آن به‌جای مدل موفق شکل `{cause, message}` دارد و باید
>   همان `message` به کاربر برسد، و پاسخی که `problems` دارد. حالت دوم دقیقاً همان باگی است که این
>   کامیت درست کرده و الان هیچ چیزی از برگشتنش جلوگیری نمی‌کند.
> - **بازنشانی آدرس باید واقعاً به پیش‌فرض برگردد.** اگر «بازنشانی به پیش‌فرض» مقدار ذخیره‌شده را پاک
>   نکند، برنامه پس از راه‌اندازی مجدد همچنان به سرور تست وصل می‌ماند — و چون این تنظیم فقط در حالت
>   دیباگ دیده می‌شود، تشخیصش سخت است. سه حالتِ «بدون override → پیش‌فرض»، «با override → مقدار جدید»
>   و «پس از بازنشانی → دوباره پیش‌فرض» باید تست شوند.

`Settings` has an in-memory implementation (`MapSettings`) that makes the repository test a few lines,
and `extractTypedData` needs only a `BaseDTO` literal and a `Json` instance — the same shape the
existing `WorkShopObjectionDTOTest` uses.

## 6. Dead defaults still pin `signOut` / `revoke` to production — Low

**File:** `core/core-network/.../apiService/UserApiService.kt:74,83`

```kotlin
@Url url: String = "${NetworkConstants.BASE_URL_ACCOUNT}signout",
…
@Url url: String = "${NetworkConstants.BASE_URL_ACCOUNT}revoke",
```

This MR changed both call sites in `AuthRemoteDataSourceImpl` to pass `url` explicitly from the

**Suggested change:** drop the default values so `url` is a required parameter, the same way

## What was done well

- **The override is threaded through *every* consumer, not just the obvious ones.** Main, auth,
  health and AI HTTP clients, the health Ktorfit instance, the authorize URL, the sign-out URL, and
  all four `AuthRemoteDataSourceImpl` endpoints — including the two that previously relied on the
  api-service default parameter. It would have been easy to change the main client and miss the OAuth
  paths, which are the ones that actually matter when pointing at a test realm.
- **The restart asymmetry was noticed and written down.** `BaseUrlPresets.requiresRestart` carries a
  comment explaining exactly why MAIN/HEALTH_PROFILE/AI need a restart (baked into Koin singletons)
  and ACCOUNT does not (resolved per call), and the UI surfaces that to the user via
  `developer_options_restart_notice` instead of leaving them to guess.
- **`extractTypedData` is a real fix with the reasoning recorded.** The KDoc names the gateway, the
  error envelope shape (`data` as `{cause, message}` instead of the success DTO), and why decoding is
  deferred until the status is known — a `SerializationException` was previously thrown before the
  backend's own message could be read. The `BaseDTO<JsonElement?>` change to the two change-mobile
  endpoints follows from that rather than being an unrelated loosening.
- **`DEFAULT_AUDIENCE` was centralised while being fixed.** The two `UserApiService` methods had the
  audience string duplicated as literals; they now both reference the constant, so the next audience
  change is one edit.
- **Correct layering for the new feature.** Interface in `core-domain`, implementation in
  `core-datastore` bound via `datastoreModule`, presets and UI in the feature module, and the profile
  screen reaching it through a navigation callback rather than a direct import.
