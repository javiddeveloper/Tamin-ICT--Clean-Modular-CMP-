## 1. `isFeatureEnabled`/`getDisabledMessage` still swallow cancellation — Low

**File:** `core/core-data/src/commonMain/kotlin/com/tamin/taminhamrah/data/feature/FeatureManagerImpl.kt:31-52`

```kotlin
override suspend fun isFeatureEnabled(flag: FeatureFlag): Boolean {
    return try {
        getFeatureStatus(flag).first() is FeatureStatus.Enabled
    } catch (e: Exception) {
        false
    }
}

override suspend fun getDisabledMessage(flag: FeatureFlag): String? {
    return try {
        getFeatureStatus(flag).first().serverMessage
    } catch (e: Exception) {
        null
    }
}
```

Both predate this MR and are unchanged by it, but this MR adds `observeFeatureStatuses` right
above them in the same file, which does rethrow cancellation correctly:

```kotlin
.catch { e ->
    if (e is CancellationException) throw e
    emit(flags.associateWith { FeatureStatus.Enabled })
}
```

Since `CancellationException` is a subtype of `Exception`, a coroutine cancelled while either of
the two suspend functions is in flight (e.g. the screen closes mid-check) gets swallowed and
reported as `false`/`null` instead of propagating.

**Suggested change:**

```kotlin
} catch (e: CancellationException) {
    throw e
} catch (e: Exception) {
    false // or null
}
```

**Round 2:** fixed exactly as suggested in both functions, and also in the third, sibling
function in the same file (`getFeatureTitle`) that has the identical bare `catch (e: Exception)`
and wasn't called out by name in round 1 but shares the same bug.

## 2. Hardcoded fallback toast uses the raw enum name — Low

**File:** `feature/profile/src/commonMain/kotlin/com/tamin/taminhamrah/feature/profile/ui/ProfileViewModel.kt:218`

```kotlin
else -> sendEvent(ProfileEvent.ShowToast("به زودی: ${item.name}"))
```

Predates this MR (only the surrounding `when` was moved into a new `navigateTo` function, not
this branch), but it's a literal Persian string built from `ProfileMenuItem`'s enum constant name
(e.g. `SOME_ITEM`), not a `stringResource`, and would show the English identifier to the user for
any menu item that falls into this branch.

**Suggested change:** move this to a `stringResource` with a format arg for the item's own
display name, the same way every other row in this screen reads its label.

**Round 2:** `navigateTo`'s `when` already has a branch for every one of `ProfileMenuItem`'s 18
entries, so this `else` was unreachable dead code, not a real fallback path — removed instead of
localized, since there's nothing left to build a display string for.

## What was done well

- **`FeatureGate`/`toGate()` gives every screen (profile, treatment, home) one shared decision for
  what a gated tap does**, instead of each screen re-deriving open/warn/block/web-only logic from
  `FeatureStatus` on its own — `TreatmentViewModel.openGated`, `ProfileViewModel.handleItemClick`
  and `HomeViewModel.handleGatedSectionClick` all read the same way.
- **The debug-only override screen is gated exactly like the existing payment/agent-mock
  toggles**: `FeatureFlagOverrideRepositoryImpl`'s in-memory cache starts empty when `!isDebug`,
  and `setOverride` early-returns in a release build, so a value left over from a prior debug
  install can't affect a release build regardless of what's in storage.
- **`TreatmentViewModel.Reset` correctly preserves `featureStatuses` across a reload** instead of
  wiping it back to the initial shimmer state — a real edge case, not just a happy-path fix.
- **`GetVisibleServicesUseCase`/`DedicatedScreenFlags` avoids a module-boundary violation**
  (`feature:taminServices` cannot import `feature:profile`/`feature:treatment`) by keeping the
  single source of truth in `core-domain`, with a KDoc explaining exactly when it would need to
  grow a new audience.
- **`MockMenuDataCoverageTest` asserts every real (non-provisional) `FeatureFlag` has a mock-menu
  row** — the kind of exhaustiveness check that catches a forgotten flag immediately instead of at
  runtime.
- The provisional-id block in `FeatureFlag` documents exactly what happens when the real backend
  registers an id (only the enum entry and its mock row move — nothing that reads the flag does).
