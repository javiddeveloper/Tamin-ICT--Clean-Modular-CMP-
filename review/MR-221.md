## 2. Guardian letter-number validation is weaker than legacy — Medium

**File:** `core/core-ui/src/commonMain/kotlin/com/tamin/taminhamrah/model/contractFlow/GuardianFormPR.kt:20-25`

```kotlin
val isValid: Boolean
    get() = nationalId.length == 10 &&
        letterNumber.isNotBlank() &&
        ...
```

Same finding as MR !219 item 3 (that MR's fix has since merged to `develop`, but this branch predates
it and hasn't picked it up — see the merge-state note above). `old_android`'s

## 5. Hardcoded Persian substring for text highlighting — Low

**File:** `core/core-ui/src/commonMain/kotlin/com/tamin/taminhamrah/ui/contractFlow/ContractTermsStepContent.kt:142`

```kotlin
private fun buildInfoBannerText() = buildAnnotatedString {
    val colors = LocalTaminColors.current
    val template = stringResource(Res.string.contract_terms_info_banner)
    val highlightWord = "مقررات و ضوابط انعقاد قرارداد"
    val index = template.indexOf(highlightWord)

    if (index == -1) {
        append(template)
    } else { ... }
```

`highlightWord` is a Persian literal that must exactly match a substring baked into the
`contract_terms_info_banner` XML resource. Any future wording change to that resource silently breaks
the highlight (`indexOf` returns `-1`, falling back to unstyled plain text — not a crash, but a visual
regression nobody will notice until a translator or copywriter touches the string). It's also a literal
duplicating resource content rather than sourcing it from `strings.xml`.

**Suggested change:** split `contract_terms_info_banner` into three resource parts (prefix / highlighted
phrase / suffix) and source the highlighted phrase from its own resource instead of a Kotlin literal,
so the two stay coupled through the resource file rather than through a hidden string match.
