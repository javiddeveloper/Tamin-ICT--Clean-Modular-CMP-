## 1. Doc comment misattributes the field-swap bug to `old_android` — Low

**File:** `core/core-ui/src/commonMain/kotlin/com/tamin/taminhamrah/model/treatment/ElectronicPrescriptionPricePR.kt:6-11`

```kotlin
/**
 * One record's price, as `patient-history/price` reports it.
 *
 * The field names do not say whose share is whose, and the old app read them the wrong way round.
 * Checked against live data: every item's `ssoPayment` is its patient share, and they add up to
 * [headInsuPayment] exactly, while [headSsoPayment] is [requestPrice] less that.
 */
```

Checked `old_android`'s `ElectronicPrescriptionDetailFragment.kt` (`initialCastsView()` /
`showResultPrice()`, lines ~127-263): the legacy screen labels the box bound to `headInsuPayment` as
«جمع سهم بیمه شده» (your/insured share) and the box bound to `headSsoPayment` as «جمع سهم سازمان»
(organization's share) — exactly the reading this MR's fix now uses, **not** the backwards reading the
comment says the old app had. (The legacy Kotlin view-binding IDs happen to be named the *opposite*
of what they're bound to — `insuredShareView` shows the organization's share and vice versa — which
is probably where the "old app got it backwards" impression came from, but the on-screen label,
which is what a user actually sees, was already correct.)

The fix itself is right and verified independently against live data, so there's no functional
problem here — this is purely about the comment leaving a wrong trail for the next person who reads
it, potentially making them look for this same bug in the legacy app again.

**Suggested change:** reword the comment to say the swap was introduced in the KMP port itself (not
inherited from `old_android`), so a future reader doesn't waste time re-checking legacy for a bug that
isn't there.

## 2. `CancellationException` still swallowed in this file's other methods — Low (pre-existing)

**File:** `feature/treatment/src/commonMain/kotlin/com/tamin/taminhamrah/feature/treatment/ui/prescriptions/PrescriptionsViewModel.kt:68-72,200-207,220-227,237-244`

Not introduced by this MR, and not blocking it — flagged because this MR just rewrote
`selectPrescription()` right above these to correctly let cancellation propagate (moving from
try/catch to `Flow.catch`, which never intercepts `CancellationException`), while
`getLoggedNationalCode()`, `loadRecordPrices()`, `downloadPdf()`, and `downloadLabResult()` in the
same file still use a bare `catch (e: Exception)` that would catch and swallow a real cancellation —
the recurring pattern found in nearly every MR reviewed this cycle. Since the file is already being
actively worked on, it would be low-cost to fix alongside rather than in a separate pass.

**Suggested change:** add `catch (e: CancellationException) { throw e }` before the general catch at
each of the four sites, or switch them to `Flow.catch` the way `selectPrescription` now does.

## What was done well

- **A real, previously-invisible bug is fixed and regression-tested**: `selectPrescription()` used to
  `collect` the detail flow and the price flow sequentially inside a `try`, but both repositories
  answer from a Room cache and then keep watching it — neither flow ever completes — so the price
  request was never made at all as long as the screen was open. Merging the two flows instead fixes
  it, and `PrescriptionsViewModelTest.kt` gained
  `testSelectPrescription_loadsPriceWhileTheDetailFlowIsStillOpen` specifically for this.
- **The field-swap fix was verified against live data before being applied**, not just assumed from
  the field names — exactly the kind of check this cycle's reviews have repeatedly found missing in
  faithfully-ported-but-wrong legacy values. The result also happens to match what `old_android`
  actually displayed (see item 1's nuance on the *comment*, not the fix).
- **The record-detail and records-list totals now source from the same `patient-history/price`
  response** instead of the list independently summing item prices — confirmed against
  `old_android`'s `ElectronicPrescriptionDetailFragment.showResultPrice()`, which does the same
  (reads the three summary figures straight from the price endpoint rather than summing items).
- **`PrescriptionSelected` now clears the previous record's details/price** before the new record's
  own load starts, so a slow answer for one record can no longer show under a different record's
  heading — a subtle correctness fix riding along with the visual polish.
- **No hardcoded Persian strings in production code** — the only Persian literals in the diff are
  inside `@Preview`-only composables (sample/mock data), consistent with the rest of this codebase's
  convention.
- **Build and full existing test suite pass** across `:feature:treatment`, `:core:core-ui`,
  `:core:core-domain`.
