## 1. Self-inquiry path (empty son list) is missing and submit silently no-ops — High

**File:** `feature/inquiryEducation/src/commonMain/kotlin/.../ui/InquiryEducationViewModel.kt:93-121`

```kotlin
private suspend fun FlowCollector<PartialState>.submit() {
    if (uiState.value.isSubmitting) return
    val state = uiState.value
    val sonError = if (state.sons.isNotEmpty() && state.selectedNationalId.isNullOrBlank()) {
        getString(Res.string.inquiry_education_error_select_son)
    } else null
    val codeError = if (!state.educationCode.matches(EDUCATION_CODE_REGEX)) {
        getString(Res.string.inquiry_education_error_code)
    } else null
    if (sonError != null || codeError != null) {
        emit(PartialState.FieldErrors(sonSelectionError = sonError, educationCodeError = codeError))
        return
    }
    val nationalId = state.selectedNationalId ?: return   // <-- silent no-op when sons is empty
    ...
```

`InquiryEducationFormStep.kt` always renders the education-code input (`EducationCodeSection` is
outside the `sons.isNotEmpty()` branch), and the submit button in `InquiryEducationScreen.kt:234`
is enabled regardless of `state.sons`. So when the son list comes back empty, a user can type a
valid 10-character code and tap submit: `sonError` stays `null` (the check is gated behind
`state.sons.isNotEmpty()`), `codeError` is `null`, so both guard clauses pass, and the function
falls through to `val nationalId = state.selectedNationalId ?: return`, which is `null` — the
function returns with no emission at all. No loading state, no error message, nothing — the submit
button just does nothing.

> **یافته‌ی بیزینسی (فارسی):** در `old_android` (`InquiryStudyCodeFragment`/`ViewModel`)، وقتی کاربر
> هیچ فرزند پسری برای انتخاب نداشته باشد (لیست خالی)، فیلد انتخاب فرزند مخفی می‌شود ولی ولیدیشن
> "انتخاب فرزند" اصلاً بررسی نمی‌شود و مقدار پیش‌فرض `selectedDependent = "1"` (یعنی «خود
> بیمه‌شده») به سرور ارسال می‌شود — یعنی کاربری که فرزند پسر ثبت‌شده‌ای در سیستم ندارد هم می‌تواند
> برای «خودش» استعلام گواهی اشتغال به تحصیل را ثبت کند. در پیاده‌سازی جدید این مسیر کلاً حذف شده:
> وقتی لیست فرزندان خالی است، فقط یک پیام «فرزند پسری یافت نشد» نمایش داده می‌شود و اصلاً راهی برای
> ثبت استعلام برای خود شخص وجود ندارد — علاوه بر این، اگر کاربر کد رهگیری را وارد کند و دکمه‌ی
> استعلام را بزند، هیچ اتفاقی نمی‌افتد (نه خطا نشان داده می‌شود، نه لودینگ نشان داده می‌شود)، که
> از نظر کاربر یک باگ واقعی به نظر می‌رسد.

**Suggested change:** decide whether self-inquiry is intentionally out of scope for this MR (the
strings are all worded around "فرزند پسر", so it may be a deliberate product decision), and either:
- restore the old behaviour — when `sons` is empty, allow submit with an implicit "self" code
  (matching `selectedDependent = "1"` / `apiCode = ""` from old_android), or
- if self-inquiry is intentionally dropped, at minimum disable the submit button (or the whole
  form) when `sons` is empty instead of leaving a silently-broken submit path, and update
  `inquiry_education_empty_sons` copy accordingly.

No test in `InquiryEducationViewModelTest.kt` exercises "submit with a valid code while `sons` is
empty" — the existing `load_error_staysOnForm` test only asserts the loading state, not what
`Submit` does afterwards.
