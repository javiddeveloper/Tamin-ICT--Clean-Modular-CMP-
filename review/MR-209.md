## 3. Non-unique `key` in the agreements list — High

**File:** `feature/taminServices/src/commonMain/kotlin/com/tamin/taminhamrah/feature/taminServices/employerOnlineServices/ui/EmployerOnlineServicesScreen.kt:265`

```kotlin
itemsIndexed(
    visibleAgreements,
    key = { _, item -> item.workshopId + "-" + item.branchCode },
)
```

`workshopId` + `branchCode` is not a unique identifier for a row here:

- The service is `get-all-employer-agreement-by-national-id`, which returns **one row per
  agreement**, and an employer can hold more than one agreement against the same workshop — that is
  exactly the premise of the sibling endpoint
  `get-employer-agreement-by-workshop-id-and-branch-code`, which lists *several* agreements for
  *one* workshop.
- Independently, `EmployerAgreementDN` maps missing values to blanks, so any two rows whose
  `workshop` block is absent both produce the key `"-"`.

In either case `LazyColumn` throws `IllegalArgumentException: Key "…" was already used` and the
screen crashes on first composition — not on an exotic path, but as soon as an account has two
agreements on one workshop.

**Suggested change:** key by something genuinely unique (`pymseq` — the DTO already models it as
`paymentSequence` on `EmployerAgreementByWorkshopDTO`; add it to `EmployerAgreementDTO`/`DN` if the
list endpoint returns it), or include the index:

```kotlin
key = { index, item -> "${item.workshopId}-${item.branchCode}-$index" },
```

## 5. An expired security ticket is not blocked — Medium

**File:** `feature/taminServices/src/commonMain/kotlin/com/tamin/taminhamrah/feature/taminServices/employerOnlineServices/ui/EmployerAgreementRequestScreen.kt:305`

```kotlin
if (secondsLeft > 0) CountdownPill(secondsLeft) else ResendCodeButton(...)
```

When the countdown reaches zero the pill is swapped for "ارسال مجدد", but nothing else changes: the
OTP field stays enabled and "تأیید و مشاهدهٔ تعهدنامه" stays enabled, so the user can submit a code
that is already known to be dead and gets back a raw server error instead of a clear one.

> **مغایرت بیزینسی:** در نسخهٔ قدیمی وقتی تایمر پنج‌دقیقه‌ای تمام می‌شد، یک پیام خطای صریح نمایش داده
> می‌شد («فرصت ارسال بلیت امنیتی به پایان رسید، لطفاً دوباره تلاش کنید») و مرحله به حالت اول برمی‌گشت
> تا کاربر مجبور شود بلیت جدید بگیرد. در نسخهٔ جدید کاربر می‌تواند کد منقضی‌شده را ارسال کند و فقط یک
> خطای خام سرور می‌بیند، بدون اینکه بفهمد مشکل، انقضای کد بوده است.

A smaller, related point on the same block: `secondsLeft` is composition-local state, so the countdown
restarts from 05:00 whenever the code screen leaves and re-enters composition, showing time the ticket
no longer has. Deriving it from an "issued at" timestamp held in the ViewModel state would keep it
honest.

**Suggested change:** when `secondsLeft == 0`, disable the OTP field and the verify button, and show
the expiry message next to the resend action.

## 12. `@Immutable` state holding plain `List` / `Map` — Low, needs confirmation

**File:** `feature/taminServices/.../contract/EmployerOnlineServicesContract.kt` — `AgreementsListUiState.agreements`,
`ContractRowsUiState.rows`, `AgreementRequestUiState.workshopsWithoutContract`,
`EmployerOnlineServicesUiState.errors`, and `AgreementDocumentPR.clauses`.

These are declared `List` / `Map` inside `@Immutable` classes. `kotlinx.collections.immutable` is
already a dependency here — `EmployerAgreementRequestScreen.kt` imports `persistentListOf` for the
step indicator — and MR !201 established `ImmutableList` on Compose state classes as the convention.

`@Immutable` is a promise to the compiler rather than a guarantee, so this is not a correctness bug
today; it is flagged for consistency with that decision. If the team's position is that `@Immutable`
on the holder is sufficient, say so and it will be marked `➖ rejected`.

## What was done well

- **Layering is exactly right.** DTO → DN → PR with one mapper per hop, a use case per call, the
  repository behind an interface, Koin registration in the module the docs point at. Nothing in the
  feature reaches past its layer.
- **Per-source error tagging.** `EmployerOnlineServicesErrorSource` plus the `errors` map means a
  failed identity call does not blank the agreements list, and a retry re-issues exactly one call.
  That is a real improvement over the legacy screen, which failed as a whole.
- **The legacy wire quirks were found and documented rather than "fixed".** `wokshopId`, `emailaddr`,
  `mobileno`, and `mobileNo` on the submit body each carry a comment saying the spelling is the
  server's and must not be corrected. That is the kind of note that saves the next person an
  afternoon.
- **Test breadth outside the feature module.** DTO deserialisation against real JSON fixtures, mapper
  edge cases (missing nested blocks, omitted fields), repository paging shape, use-case pass-through
  and error propagation — and the fixtures are actual server payloads.
- **`LegalDocumentRepository`.** Pulling the تعهدنامه text out of the screen and behind a repository
  a real endpoint can replace without touching callers is the right call, and the reason item 2 is a
  content problem rather than an architecture one.
- **`TopArea` reuse.** The measured, folding header follows `docs/vault/TopArea-System.md` and the
  `LegalRepresentativeWorkshopsScreen` precedent instead of reinventing it.
