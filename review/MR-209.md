## 5. An expired security ticket is not blocked — Medium → fixed

**File:** `feature/taminServices/.../ui/EmployerAgreementRequestScreen.kt` (`CodeEntryStep`)

```kotlin
val isTicketExpired = secondsLeft <= 0
...
primaryEnabled = request.isCodeComplete && !request.isSubmitting && !isTicketExpired,
...
enabled = !request.isSubmitting && !isTicketExpired,
...
if (isTicketExpired) { Text(stringResource(Res.string.employer_online_services_request_code_expired), ...) }
```

The OTP field and the verify button both disable on expiry, and a new
`employer_online_services_request_code_expired` message explains why — closing the main defect.

**Not addressed, and not part of what was asked:** the smaller sub-point noted in round 1 — that
`secondsLeft` is `remember(request.ticketNonce)`-scoped composition-local state, so leaving and
re-entering `CodeEntryStep`'s composition (e.g. backgrounding the app) resets the visible countdown to
05:00 without a new ticket actually having been issued. This was flagged as a secondary, smaller point
in round 1's item 5, not the main finding, so the main item is recorded as fixed; re-raising the timer
source as its own low-priority note for whenever this screen is next touched, not blocking here.

Closed (main defect).

## 7. Search narrowed to one loaded window — Medium → fixed

**File:** `feature/taminServices/.../ui/EmployerOnlineServicesViewModel.kt`

This is a real rewrite, not a patch: `WORKSHOP_FULL_PAGE_SIZE` (the 100-row single-shot shortcut) is
gone from `WorkshopQueries.kt` entirely, and the agreements list, the contract-rows list, and the
step-2 without-contract list are all now driven by a shared `Paginator<T>` (the same engine
`MyInboxViewModel` already uses) with `WORKSHOP_PAGE_SIZE = 10` real pages.

Crucially for this item: `agreementsSearch` (کد کارگاه / کد شعبه) is now threaded into the query the
paginator sends to `getEmployerAgreementsUseCase` —

```kotlin
loadPage = { query ->
    val page = getEmployerAgreementsUseCase(
        WorkshopListQuery(
            workshopId = agreementsSearch.workshopCode.ifBlank { null },
            branchCode = agreementsSearch.branchCode.ifBlank { null },
            page = query.page,
            pageSize = query.limit,
        ),
    )
    ...
}
```

— so a search now re-queries the server from page one (`searchAgreements_reQueriesTheServerFilteredFromPageOne`,
`clearAgreementsSearch_returnsToTheUnfilteredFirstPage`) rather than filtering an in-memory window. An
employer with more than 10 agreements can now find one on any page.

Closed.

## What was done well (round 2)

- **Item 7 was not patched — it was properly rebuilt.** Rather than pushing the search criteria into
  the existing 100-row shortcut, the whole list-loading approach for all three lists in this feature
  was replaced with the project's existing `Paginator` (already proven in `MyInboxViewModel`), and
  `WORKSHOP_FULL_PAGE_SIZE` was deleted outright rather than left as dead weight for the next reader
  to wonder about. That is a materially bigger fix than the round-1 suggestion asked for, and it is
  the right one.
- **Item 6's fix was bundled with the pagination it depended on** rather than being a narrow
  clickable-row patch that would have needed touching again a week later.
- **The non-unique-key class of bug (item 3) did not recur** in the two new/changed lazy lists the
  pagination rewrite introduced — both were keyed correctly the first time.
- **Item 9's cleanup was thorough**, not just deleting the call site: DTO, mapper, presentation model,
  repository interface + impl, use case, DI registration, and tests were all removed together, with a
  `grep` leaving nothing pointing at the deleted chain.
- **Item 8's test does more than the letter of what was asked** — it also checks that a retry after a
  failed submit does not force the user back through OTP, which is the detail that actually makes the
  fix worth having (a "just add a failing-submit test" ask could have stopped at asserting the error
  state alone).
