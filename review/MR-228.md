## 1. Swallowed CancellationException in coroutine catch blocks — High

**File:** eature/taminServices/src/commonMain/.../WorkersPaymentViewModel.kt (lines 89 and 126)

`kotlin
// current code in loadPaymentInfo and payItem:
            } catch (e: Exception) {
                val message = e.toSingleLineMessage()
                emit(PartialState.Error(message))
                sendEvent(WorkersPaymentEvent.ShowToast(message))
            }
`

Catching Exception broadly without rethrowing CancellationException breaks structured concurrency. When the ViewModel is cleared (e.g. user navigates away before the network call completes), the network call is cancelled and throws CancellationException. The catch block intercepts it, attempts to send an error event (and show a toast), and swallows the cancellation.

**Suggested change:**
Rethrow CancellationException in both catch blocks (inside loadPaymentInfo and payItem):

`kotlin
// proposed code
            } catch (e: Exception) {
                if (e is CancellationException) throw e
                val message = e.toSingleLineMessage()
                emit(PartialState.Error(message))
                sendEvent(WorkersPaymentEvent.ShowToast(message))
            }
`
